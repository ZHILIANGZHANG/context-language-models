# Qwen3-8B 自主管理 KV：实际运行代码与已完成 SFT 结果

本目录归档 2026-11-16 完成的 **SFT 每 50 步验证重启版**。训练、200 次评测已完成；此处不宣称原始权重基线对比或 RL 已完成。服务器现有任务不因本次发布而重新启动。

## 先读结果限制

**名为 `full` 的 91% 结果不是严格“完整历史、不换页”的 Full 基线。** 实际代码中 `kv_tools=False` 只隐藏工具定义，执行器仍接收模型输出的 KV 调用。这 50 次名义 Full 评测实际执行了 461 次 `kv_out`、6 次 `kv_in`。其正确名称应为“**不设预算上限、仍接受模型换页的 SFT 模型**”。不能据此宣称预算版相对严格 Full 的准确率或显存收益。

预算版原本就允许模型换页，其逐题答案统计可以复核，但低预算下存在强制驱逐、截断和非法动作。因此不能把任务正确率等同于 KV 决策正确率。`Recent`/`QuestPage` 使用同一个执行器，也必须先审计未经声明的模型换页，才能作为纯系统策略比较。旧审计文件的 `protocol_under_five_percent` 仅是错误计数条件，**没有检验工具权限隔离**。

此次发布保留实际运行源码及原始记录，未事后修改算法、分数或原始日志。修复工具执行权限并补做严格对照是后续工作，不能把本目录当作该修复已经完成的证据。

## 已完成结果

同一批 50 个独立 warehouse 世界（seed 100000–100049），每个世界 4 次任务决策；每种配置共 200 次决策。准确率衡量任务答案是否正确。下面的“全对世界”要求同一世界的 4 次决策全部答对。

| 配置 | 正确决策 | 准确率 | 全对世界 | 平均峰值驻留 token | 强制驱逐次数 / 受影响世界 |
|---|---:|---:|---:|---:|---:|
| 不设预算上限、仍接受模型换页（原始标签 `full`） | 182/200 | 91.0% | 34/50 | 7,225.26 | 0 / 0 |
| 模型自主换页，预算系数 0.60 | 169/200 | 84.5% | 29/50 | 4,498.36 | 14 / 1 |
| 模型自主换页，预算系数 0.40 | 171/200 | 85.5% | 26/50 | 4,471.54 | 30 / 6 |
| 模型自主换页，预算系数 0.25 | 158/200 | 79.0% | 16/50 | 3,762.56 | 194 / 37 |

| 配置（原始标签） | 非法动作 | KV 错误 | 被截断 token | 成功 kv_out | 成功 kv_in | note |
|---|---:|---:|---:|---:|---:|---:|
| full@1.0 | 0 | 1 | 0 | 461 | 6 | 0 |
| model@0.6 | 0 | 0 | 771 | 754 | 25 | 31 |
| model@0.4 | 3 | 5 | 1,366 | 756 | 23 | 13 |
| model@0.25 | 39 | 31 | 7,958 | 790 | 20 | 15 |

预算是 `t1_budget` 定义的 **固定模板开销 + 系数 × 环境正文 token 数**，不是 GPU 显存的百分比，也不等于完整模型上下文长度的精确百分比。系数 1.0 返回无限预算。峰值驻留量以 token 计，不是 GiB；日志中的成本是 `episode_cost` 的解析模型（κ 采用 batch=32），不是实测 CPU↔GPU 传输延迟，也不代表推理实际 batch 为 32。

评测使用 Qwen3-8B + 最终 SFT LoRA，SDPA，非 thinking 格式，temperature=0.6、top_p=0.95、top_k=20、每轮最多生成 1024 token、每世界最多 60 轮。每世界按 seed 建立生成器，配对配置采用相同初始采样 seed；换页导致生成路径不同，不保证后续随机数一一配对。全部 200 条轨迹未超过 32K，核对了实际答案、环境正文、预算、原始散列和解析成本。不同预算之间的少量分差不作显著性结论；四次决策属于同一世界，不能作为 200 个完全独立样本。

## SFT 训练设计

- 起点：原始 `Qwen3-8B`，不是先前已停止的 SFT checkpoint；GPU 0/1/2 三卡，1 epoch，431 次真实优化更新。
- 数据：2,400 条训练轨迹 / 240 条 held-out 轨迹，分别来自 999 / 99 个世界。含不同预算、换出、换入及组合行为；同一任务的多预算版本保留在同一数据划分。训练正文不是开放域真实 QA，而是可验证状态的 T1 warehouse 合成任务。
- 教师动作来自经过检查的 oracle 计划；GPU 模型改写行动理由。并非模型自主推理产生全部标准动作。对实际生成轨迹进行事实、协议、状态摘要、预算与动作语义过滤；最终录用数据要求零 fallback。详细计数、种子覆盖和 SHA 在 `data/data-accepted.json`。
- 全部 480 条无预算训练轨迹，加上 0.60/0.45/0.35 各 320 条 out、320 条 both。实际包含的换入与组合 turn 另有覆盖核验，不能只按轨迹名推断每一步行为。
- LoRA rank=64，alpha=128，lr=1e-4，seed=0；梯度检查点、BF16、FlexAttention，按轨迹打包，上限 32,768 token。跨样本隔离的可见页面掩码由记录重建；只对指定 assistant token 计算 CE。单纯 `next_events` 的监督保留率为 25%，输入和可见性记录不改写。
- 每完成 50 次更新评估全部 240 条 held-out 轨迹，按受监督 token 加权汇总验证 CE，同时保存 LoRA；最后第 431 步再验证和保存。最终评测使用 **431 步最终权重**，没有用测试答案选 checkpoint。
- checkpoint 是可加载评测的 LoRA 权重，**不包含完整 optimizer 恢复状态**。权重及训练语料保留服务器，本次 Git 归档包含配置、哈希、指标与评测原始记录，不包含大模型权重或完整训练语料。

## 代码、版本与复核

仓库 `self_paging/` 是服务器实际部署代码：页面生命周期、KV backing store、确定性采样、观测型系统 pager、批处理支持、分布式梯度/验证汇总、周期 checkpoint 和 RL CPU 数据准备均包含在内。部署代码较上游包含新增功能，不能据此声称每个功能都完成了真实任务实验。

- SFT 源码：上游 `797680fc691514587fb8cc298236c624ac3bbac8` 加运行修复，91 文件 SHA 清单在 `provenance/val50-source-manifest.json`。
- 后续基线/RL 准备：93 文件 SHA 清单在 `provenance/rl-prep-source-manifest.json`。引入上游 `223cc65` 的 Belady 修正并增加 CPU RL 筛选代码。相对 SFT 仅 `agent/pagers.py` 内容不同，另新增两个 RL 文件。旧 pager 原样保存于 `provenance/sft_source_override/`，可以重建原 SFT 源码。
- `server_helpers/` 为从服务器读取并逐字节核对的调度、生成、过滤、训练、验证和监控脚本。它们保留原服务器绝对路径、锁、STOP 和防重复启动检查，**不是可直接在其他机器运行的通用启动器**。入口、依赖和状态见该目录说明。
- `provenance/env-spec.json` 是最初创建时的环境约定，内含最早源码指针；它不替代上述两个后续源码清单。实际已通过的 CPU/GPU 检查证据随包保存。
- `provenance/server-collection.json` 逐文件记录来源、字节数和 SHA；`raw/*.jsonl.gz` 解压后的字节与服务器原始 JSONL 完全一致。

在此提交的仓库根目录执行：

```bash

```

只使用 CPU 和 Python 标准库，重核源文件及证据 SHA、200 个唯一配置/世界键、800 个任务答案、成本、训练步数和验证云端回读，然后生成 `tables/` 中的 JSON/CSV。`tables/verification.json` 的通过含义是归档与计数通过；名义 Full 的科学限制仍然存在。更新源码后须切回本提交才能进行原版本散列复核。

## RL / 基线尚未结算

原始权重只继续 Recent 与 QuestPage 两种代表性方法，50 世界 × 3 预算 × 2 方法=300 次。此处不归档其未完成分数，不声称严格比较已验收。QuestPage 为页面 key 摘要近似，不应称为完整复刻任意外部实现。

RL CPU 准备已完成：13,900 个候选条件，选出 5,000 个训练条件；预算和 2–6 次决策难度格子无缺口。OOD 的 300 个条件只有 1 个满足当前 32K 支持范围，故 OOD 尚不可作为已就绪集合。保存 `rl_data/` 的实际验收和分割报告，不在本次发布中伪造 GPU profile 或 RL 训练成绩。

GRPO 后续仍需处理/核验：任务奖励相同的组目前会被过滤（可能丢掉全成功组的效率信号）、效率奖励尚未同时按协议可靠性严格门控、实际采样器与新 pool 的接线、BF16 rollout/recompute logprob 及分布式更新检查。当前队列完成基线后接的是 **64×4 数据诊断推理**，不是自动开始正式 RL。详见 `provenance/RL-DATA-PROPOSAL.md`；其中计划部分不能当作已执行事实。
