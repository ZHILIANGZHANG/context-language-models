# 和 KV 剪枝 / 换页基线的公平对比协议

2026-11-16。回答的问题是：我们的方法（模型自己用 `kv_out` / `kv_in` / `note` 管理 KV，并经过 SFT + RL 训练）怎样和 H2O、SnapKV、StreamingLLM、Quest 这类系统决定的 KV 剪枝方法公平比较。执行实验的 agent 在跑主表之前，要先按本文补齐基线和对照（§7 的开发任务）。

---

## 0. 不公平会来自哪里

| 来源 | 具体表现 | 对策（章节） |
|---|---|---|
| **训练** | 我们在 T1 上做了 SFT + RL，基线是没有训练过的底座。赢了可能只是因为"学会了这个任务"，而不是"学会了管 KV" | 训练对齐的对照（§2） |
| **权重** | 基线用底座，我们用微调后的权重 | 同权重对照：基线也跑在我们的 checkpoint 上（§2） |
| **预算口径** | 我们的预算包含页头、目录、仪表盘、控制 token；token 级剪枝没有这些开销。反过来，基线以 token 为粒度，比按页更灵活 | 统一用"实际驻留的 KV token 数"计量，画曲线，不只比一个点（§3） |
| **信息** | 我们看得到页头摘要；基线打分时能不能看到问题、什么时候打分 | 所有方法看到同样的渲染文本；规定打分时机（§4） |
| **调参** | 我们的方法调过，基线用默认参数 | 同样的开发集、同样的调参次数（§5） |
| **基准** | T1 是我们自己设计的，延迟生效的隔离通知恰好是注意力淘汰最怕的情形 | 加上对相似度检索友好的 T1b，以及不是我们设计的基准（§6） |
| **实现** | 基线是我们自己写的近似版本 | token 级的忠实实现，能用公开实现就用（§1、§7） |

## 1. 基线清单

| 类别 | 方法 | 粒度 | 可逆 | 是否看问题 | 实现状态 |
|---|---|---|---|---|---|
| 上界 | Full（不设预算） | — | — | — | 有；执行器已修好，是严格基线 |
| 上界 | Belady（用未来信息换页） | 页 | 是 | 用真值 | 有（`agent/pagers.py`） |
| 窗口 | StreamingLLM（sink + 最近窗口） | token | 否 | 否 | 页级 Recent；token 级 `StreamingLLMPager`（2026-11-17） |
| 注意力淘汰 | H2O（累计注意力） | token | 否 | 否 | 页级 AttnEvict；token 级 `H2OPager`（逐层逐头） |
| 注意力淘汰 | TOVA（只看当前 query 的注意力） | token | 否 | 是 | `TOVAPager`（逐层，头平均） |
| 问题感知压缩 | SnapKV（观察窗口投票 + 池化） | token | 否 | 是 | `SnapKVPager`（逐层逐头） |
| 问题感知压缩 | PyramidKV（逐层不同预算） | token | 否 | 是 | 没做：各层保留数必须相同（cache 形状一致），见 §7 |
| 检索换页 | Quest（页级 key 上下界，每步选页） | 页 | 是 | 是 | 页级近似 QuestPage；按原文上下界打分的 `QuestPager`（16-token 块，逐层逐头，可逆） |
| 检索换页 | InfLLM / ArkVale（块存 CPU，按代表 token 取回） | 块 | 是 | 是 | 可选；QuestPage 是同一族 |
| 模型决定 · 文本 | CLM（文本编辑） | — | 否 | 模型自己决定 | 用 CLM 的 harness 在 Qwen3-8B 上重跑 |
| 模型决定 · 文本 | ACM memtool（摘要、存盘、查回） | — | 是 | 模型自己决定 | 用 ACM 的代码在 Qwen3-8B 上重跑 |
| 模型决定 · KV | **本文**：零样本 / SFT / SFT + RL | 页 | 是 | 模型自己决定 | 有 |
| 模型决定 · KV | 本文的只删版本（SideQuest 式） | 页 | 否 | 模型自己决定 | 有（`--irreversible`） |

**怎么实现 token 级基线**：
- **首选**：用公开实现的打分函数。NVIDIA 的 kvpress 实现了 SnapKV、StreamingLLM、H2O 类（ObservedAttention）、TOVA、PyramidKV 等 [K]。但它主要压缩一次性 prefill 的 prompt，用在多轮 agent 上要改成"每回合压缩一次"（§4）。只复用打分逻辑，按 license 注明出处；
- **其次**：自己实现，然后对照原论文或公开代码，在单轮长文 QA 上复现它们论文里报告的趋势，作为实现正确的证据。

## 2. 把"学会任务"和"学会管 KV"分开

只拿"我们的 RL 模型"对比"底座 + H2O"，结论会混进训练的效果。所以主表要包含下面四组：

| 组 | 权重 | 谁管 KV | 回答的问题 |
|---|---|---|---|
| A. 底座 + 各基线 | 原始 Qwen3-8B | 系统 | 这些方法在零训练时有多好（文献里的通常设定） |
| B. 我们的权重 + 各基线 | 本文 SFT / RL 的 checkpoint，不提供 KV 工具 | 系统 | 同一套权重下，"模型自己决定"和"系统决定"哪个更好。**这是最干净的一组对比** |
| C. 训练对齐的系统对照 | 同样的 SFT 数据和 RL 步数，但训练和推理时都由系统换页（H2O 或 SnapKV），模型只学做任务 | 系统 | 如果把同样的训练算力花在"让模型适应某个剪枝策略"上，能不能追上我们 |
| D. 本文 | 本文 SFT / RL | 模型 | — |

再加一个"任务能力"锚点：只用不设预算的 SFT 数据训练、推理时不设预算的模型（Full-SFT），说明任务本身能做到多好。

- **结论的写法**：D 优于 B，说明在同一套权重下，模型决定优于系统决定；D 优于 C，说明优势不是"多训练了"带来的；A 只作为文献里的参照；
- **C 的实现**：GRPO 的 `rollout_fn` 里给 `run_episode` 传入系统换页器，同时设 `kv_tools=False`；SFT 数据用同一批世界，但 oracle 只做任务，不发出 KV 动作，换页由同一个换页器完成。

## 3. 预算和代价：统一计量

- **预算 B** 是驻留 KV token 数的上限。所有方法用同一个 B，按同一个公式 `t1_budget(ratio)` 计算；
- 我们方法的页头、目录、仪表盘、控制 token、笔记**全部计入 B**，因为它们确实占 KV；基线用不到这些开销，等于多出一些可用空间。这个差别对我们不利，但正因为如此，结论才可信。同时报告"可用于内容的 token 数"；
- **主图是曲线，不是单点**：
  - 横轴：实际平均驻留 KV（`mean_resident_decode`），以及峰值驻留；
  - 纵轴：准确率；
  - 每个方法扫 5 档以上预算，比较 Pareto 前沿；
- **代价**：每个方法都报告 `episode_cost` 的 C（batch = 1 和 32 两种折算）。我们的控制 token 和笔记计入 C。基线的打分开销（算注意力、取代表 key）另外按 FLOPs 估算，单独报告，不混进 C；
- **墙钟延迟**只在接入真实推理引擎、真正把 KV 搬到内存之后才报告（项目约定）。

---

## 4. 信息和时机对齐

- **同样的输入**：所有方法看到同样的环境渲染，包括页头摘要。摘要是环境的一部分，不是我们方法独有的；
- **系统基线什么时候压缩**：和我们的方法一样，在回合之间进行。新的观察进来之后、模型开始生成之前，把驻留集压到预算以内；
- **问题感知的基线**（SnapKV、TOVA、Quest）用最近一段 token 作观察窗口，其中包括最新的观察和决策提示。这是它们能拿到的最好的"问题"信息。不允许看未来的观察；
- **不可逆**的基线一旦淘汰，就从日志里删掉（`drop`）；**可逆**的基线（Quest、InfLLM）可以每回合重新选；
- **Belady 用未来信息**，只作为上界，不参与"谁更好"的比较。

---

## 5. 调参对齐

- 每个基线都有超参：SnapKV 的窗口和池化核、H2O 的最近窗口比例、Quest 的页大小和 top-k、PyramidKV 的层间分配；
- 统一在**开发集**上调参（RL 题库里的 92000–92200），每个方法同样的试验次数上限（例如 12 组），按开发集上准确率曲线下面积选参数，然后在**测试集**（110000–110200）上报告；
- 我们方法的超参（w_credit、w_eff、温度等）也只能在开发集上选；
- 调参记录完整保存。

## 6. 基准：不能只在自己的主场比

| 基准 | 对谁有利 | 作用 |
|---|---|---|
| T1 仓库（自建） | 延迟生效的约束对注意力淘汰不利，可能对我们有利 | 主实验，并按决策类型拆开报告 |
| T1b 查找（自建） | 问题和证据字面相似，对 Quest、SnapKV 有利 | 检查我们在基线的主场是否持平 |
| LongMemEval-S（公开） | 问题最后才出现，不可逆淘汰吃亏 | 外部基准 |
| BrowseComp-Plus 评测 150 题（公开） | agent 检索，CLM、ACM 的主场 | 外部基准 |
| 单轮长文 QA（例如 RULER 或 LongBench v2，切成页流式读入） | 问题先给出时，SnapKV 是为这种设定设计的 | 基线的主场，同时验证 token 级基线实现得对 |

每个基准都报告两种设定："问题先给出"（对问题感知的基线最有利）和"问题最后给出"。

## 7. 开发任务（补进 runbook 的开发任务表）

| 编号 | 任务 | 验收 |
|---|---|---|
| **D10** | token 级驻留：`PagedKV` 加一个每个 token 的保留掩码（驻留 = 页驻留且 token 被保留），拼 cache 时按 token 下标筛选；再加一个钩子，能取到最近 k 个 query 对全部 key 的注意力 | 等价性测试：保留掩码全为真时，结果和现在完全一致；任意掩码下，等于单次前向加 token 级可见性矩阵的结果 |
| **D11** | 在 D10 上实现 StreamingLLM、H2O、TOVA、SnapKV（可选 PyramidKV），以及按原文用 key 上下界打分的 Quest | 每个方法写单元测试，用手工构造的注意力检查选中的 token；在单轮长文 QA 上复现原论文的趋势：问题感知的方法优于窗口方法 |

**D10、D11 的实现状态（2026-11-17）**：
- **代码**：`hf/logstore.py`（`set_keep`）、`hf/token_probe.py`、`agent/token_pagers.py`、`eval/token_sanity.py`，接进了 `eval/control_eval.py`；
- **云端已验收**（`tests/test_token_baselines.py`，24 项）：
  - 全真掩码时逐位相同；任意逐层、逐头掩码，再加上页级换入换出，逐步推理等于一次前向；
  - H2O 的累计注意力、窗口注意力，和参考前向的注意力逐项一致；
  - 五种方法在 T1 回合里守住预算，记录的 log-prob 等于一次前向；只有 Quest 会把 token 换回来；
  - 代价 C 只计可见的 token；
- **服务器上还要做**：用 `eval/token_sanity.py --modes oneshot` 在 Qwen3-8B 上复现论文趋势。没复现出来之前，不要报告这些基线的数字；
- **和论文的差别**：
  - 所有（层, 头）保留同样多的 token，所以 PyramidKV 没做；
  - Quest 前两层不豁免，每次在回合之间用观察窗口的 query 选一次，不是每个解码步都选；
  - GQA 下，同一个 KV 头的各 query 头的分数相加；
  - `protect_pinned`（默认开）保留结构页，和我们的预算口径一致；关掉就是论文那样的平铺序列；
  - 规则读者看不到 token 级隐藏，所以这些基线不能用规则读者判可行性，只能用模型评测；
- **训练打包**：`train/batch.pack` 还不支持 token 级掩码，遇到会报错。D12 先用页级换页器；要用 token 级方法做 C 组，得先给 FlexAttention 的 `mask_mod` 加上逐层逐头的保留表。
| **D12** | 训练对齐的系统对照（§2 的 C 组）：`train/grpo.py` 的 rollout 支持传入换页器并设 `kv_tools=False`；SFT 数据的"只做任务"版本 | 和 D 组用同样的数据、步数、种子；日志里 `kv_out` 恒为 0 |
| **D13** | 评测脚本统一：`control_eval` 支持 token 级方法、预算扫描、"问题先给出 / 最后给出"两种设定，输出曲线数据 | 所有方法同一批世界、同一套解码参数，按世界配对 |

## 8. 统计和报告

- 按世界配对：同一个世界、同一档预算下比较所有方法；
- 以世界为单位聚类做 bootstrap，给出 95% 置信区间；二值结果用配对检验；
- 抽样解码时每个世界跑 3 次；确定性的系统基线用贪心解码，同时报告抽样版本；
- 每个方法都用 `eval/error_analysis` 把错误分成"信息不在"和"推理错"，并按决策类型拆开；
- 主表的列：
  - 按决策类型的准确率；
  - 平均和峰值驻留；
  - 代价 C；
  - 控制 token 数；
  - 截断和强制换出次数；
  - 非法调用率。

## 9. 可以下的结论，和不能下的结论

| 可以说 | 前提 |
|---|---|
| 同一套权重下，模型自己决定优于系统剪枝 | D 优于 B，在多档预算下都成立，置信区间不重叠 |
| 优势不来自额外训练 | D 优于 C |
| 优势在于延迟相关的信息 | 按决策类型拆开后，差距集中在 delayed 题上，而在 T1b 上持平 |
| 可逆性有价值 | D 优于本文的只删版本，并且在"问题最后给出"的设定下差距更大 |

| 不能说 | 原因 |
|---|---|
| 比 H2O / SnapKV 更快 | HF 原型只有解析代价 |
| 全面优于 KV 压缩方法 | 如果只赢了 T1 |
| 和文献里报告的数字比 | 模型、任务、预算口径都不同，只能和我们自己在同一协议下重跑的结果比 |
