  - 本轮新找到的相关工作补进了 [related_work.md](related_work.md) §11；

> **一句话结论**
> 1. 完整历史、显式状态、CLM 可以看成三种**写入策略**：什么时候写、写到哪里、能不能删。把第三轮验证的结论放进这个框架，就能同时解释状态派在哪里赢、在哪里输，还能给 CLM 推出一个没人测过的预测（§1）。
> 2. 对 6 个候选做对抗审查后，结论比预想的窄：**CLM 的每一项优势，都能被"传统 harness 加一个设计好的工具"追平，但每一项需要的工具不同。** CLM 的真实价值是一个接口覆盖多种情况，代价是通用性带来的新失败通道（§3.3）。
> 3. 选出三个切入口，每个都配了匹配基线和预注册的判死条件（§4–§6）：
>    - **E1** 迟到的、按属性划范围的更正；
>    - **E2** 被拒之后的上下文手术；
>    - **E3** 没有线索、还会被撤销的前瞻约束。
>
>    三个可以合成一篇论文（§7）。
> 4. 三个门槛 pilot 合计约 156 个 Haiku 子 agent、约 2300 万缓存读取。每一步跑之前都要用户确认（§8）。

## 1. 统一视角：三种写入策略

### 1.1 为什么上一版论点看起来和 states、CLM 无关

1. **CLM 根本没出现**：第三轮验证没跑过 CLM，也没对它做任何预测。
2. **states 这条轴被讲没了**：结论写成"成败不在表示方式"，等于否掉了"状态 vs 历史"这个问题本身。例子又是一条通知，补救是钉一条笔记，读起来像前瞻性记忆的论文（PM-Bench、TriggerBench 一类），而不是 states 的论文。
3. **测的范围太窄**：只测了"到达时不用管、以后才关键"这一类信息，是 states 争论的边角。状态派的核心主张没碰：长程任务里，从长日志重建当前状态容易出错。

### 1.2 三种写入策略

| | 什么时候写 | 写到哪里 | 能不能删 |
|---|---|---|---|
| 完整历史（ReAct） | 从不写，决策时从日志里找 | 无 | 不删 |
| 显式状态（SKILL.state） | 每一步都写 | schema 的固定槽位 | 覆盖旧值 |
| CLM | 模型自己决定，实际多在预算提醒时（25/50/75%）成批改 | 自由文本，整个可编辑区 | 能删；删了就找不回来（作者删掉了 `ctx_archive` 开关 [R]） |

第三轮验证的结论分别落在三者身上：

- **对 states**：
  - 赢在 schema 强制每一步都写，所以槽位里的信息一定会写下，例如 L2 的 `shelf_contents`；
  - 输在槽位外的信息：L1 里，无对应字段的状态是 0/24，和历史一样 [R]；
  - 也输在写错了改不回来：错误信念中位持续 24 步，被拒后修好的只有 8/78 [R]。
- **对 history**：从不写，全靠决策时找回，而找回基本失败。提示它"回头看历史"是 0/12 [P]。
- **对 CLM**：自由文本，原则上能写下槽位外的信息，这一点比 states 强。但编辑的时机由预算和省算力决定，不由信息到达决定。prompt 明确教它"编辑会让后面的内容重算，所以攒着一起压"[R]。

### 1.3 一个只属于 CLM 的预测：省算力和保住以后才有用的信息互相冲突

按示意性成本模型（`state_study/validation/clm_cost_model.py`，不是测量），CLM 最省的日程是"每条观察读完就压"。相对定时摘要，FLOPs 为 0.91–0.98×，API 带缓存计费为 0.83–0.93×（[clm_notes.md](clm_notes.md) §13.2）。

但"读完就压"是在信息刚到、还看不出以后有没有用的时候做取舍。那条隔离通知当时"不需要动作"，最可能被压掉，而 CLM 删了就找不回。所以预测存在一条"成本 vs 延迟相关信息保留率"的前沿。

这个预测在 [clm_notes.md](clm_notes.md) §13.5 方向 1 里已经写过，本文 E3（§6）把它做成了具体探针。

### 1.4 和"从 memory 走向 state"这个趋势的关系

从 memory 走向 state，本质是从"读取时付代价"走向"写入时付代价"。state 有用，是因为它强制在信息到达时写下；下一步是让"什么时候写、写到哪里"成为可学的策略，而 CLM 正是这样的系统。

这样，主线（[research_line.md](research_line.md)）、第三轮验证和 CLM 就连成了一条线。

## 2. CLM 范式 vs 传统记忆系统和 harness

### 2.1 根本区别

| | 传统记忆系统和 harness | CLM |
|---|---|---|
| 管的是什么 | 上下文之外的存储，按需取进来；或者到预算时整段摘要 | 上下文本身，也就是模型此刻看到的东西 |
| 能做的操作 | 固定几种：存、取、改一条、摘要、折叠、隐藏、卸载 | 任意：用代码改任何一段、批量替换、重排、改写成表格 |
| 结构由谁定 | 人事先设计（记忆块、事实条目、schema） | 模型自己长出来（计分板、`## STATE` 面板、notes 角色）[N] |
| 能不能改自己的过去 | 不能。对话记录只能追加，最多整段摘要掉 | 能。自己写过的推理、做错的尝试、旧的工具输出，都能删、能改 |

竞品按"提供哪些固定操作"分成六类（详见 [related_work.md](related_work.md) §2–§3）：

| 类别 | 代表 |
|---|---|
| harness 定时压缩 | Codex、Claude Code、MEM1、ReSum、CompactionRL |
| 模型决定时机，但只能用给定工具 | SelfCompact、ACM、ContextPilot、Sculptor、Context-Folding、AgeMem |
| 记忆系统 | MemGPT/Letta（固定的核心块）、Mem0、A-MEM、检索记忆、Anthropic memory tool |
| 显式状态 | SKILL.state、PoS |
| 记录与视图分离 | Scroll、InfiAgent |
| 可见的工作区 | VISTA |

### 2.2 CLM 独有的操作（代码事实，2026-10-04 复核）

- **镜像文件**：每步之前，harness 把 system 和任务之后的所有轮次渲染进镜像文件，每轮一个 `[[CTX_TURN n role=…]]` 头（`clm/clm_harness/context_utils/context_string.py:90`，`render_editable`）。每一轮的可编辑文本包括 reasoning、内容和发出的命令（同文件的 `rendered_text`，约第 63 行起）[R]。
- **读回**：用 `parse_back` 重建消息列表（同文件第 104–139 行）。前 2 条（system 和任务）每次从原件钉回，所以规则本身改不了；清空的轮次被丢掉；相邻的同角色轮次被合并 [R]。
- **edit gate**（`clm/clm_harness/context_env/edit_gate.py`）：fit 模式下，编辑后变大也接受，只要不超预算；没有预算时一律拒绝变大（`may_grow`，第 53 行起）[R]。
- **prompt**（`clm/clm_harness/clm_agent/prompts.yaml` 第 22–24 行）：把 stale 区域（大输出、dead ends、被取代的笔记）换成简洁、具体的摘要；用代码定位文本，不要重打原文 [R]。
- **超预算提示原文**："STILL OVER … Compact more NOW (delete stale turns/outputs)"（`clm/clm_harness/context_env/env.py:306–307`）[R]。
- **回滚账本**：作者加它，是因为回滚会抹掉"刚试过什么"，模型就会重发同一条命令、陷入死循环（`clm/clm_harness/clm_agent/harness.py:418–426`）[R]。
- **作者删掉的开关**：`harness.py` 的 `_REMOVED_KWARGS` 里有 `ctx_archive`、`ctx_metadata`、`research_ledger`、`shadow_progress_guard`、`obs_offload` 等。这说明作者可能碰过本文的几个方向，要当作撞车预警 [R]。

由此，CLM 能做、而别人做不到或做起来很别扭的操作有：

1. 原地改写任意一轮里的任意片段，包括旧的工具输出和自己旧的推理；
2. 用正则、循环、辅助函数把编辑"算"出来；
3. 插入新段落、新角色，在任意位置维护 `## STATE` 面板；
4. 重排、合并、拆分轮次；
5. 在同一条命令里同时做任务动作和上下文编辑；
6. 先 `cp` 到沙箱磁盘再删，自己做可逆存档；
7. 结构按任务自己长出来。

### 2.3 CLM 天然占优的五类任务

| 任务特征 | 例子 | 记忆系统和 harness 为什么做不好 | 有没有人做过 |
|---|---|---|---|
| ① 要原地维护一个"活文档" | 棋盘、实验排行榜、计划、草稿 | 只能零碎存取；状态派要事先写好 schema | CLM 论文做了一部分（Sudoku Sketchpad、集群计分板原地改 163 次）[N]；**schema 事先不知道的情况没人做** |
| ② 既要压缩，又要逐字保真 | 证据片段、代码、数字、ID | 摘要和抽取都会改写原文 | CLM 论文已做（BrowseComp-Plus、Needle Retention）[N] |
| ③ 会犯错、会走死路 | 调试、证明、搜索、长程执行 | 错误留在记录里删不掉；清空重来又丢掉全部进度 | **没人从 CLM 的角度做**（后来发现单个成分有人做过，见 E2） |
| ④ 观察量大、整理方式重复 | 日志、批量搜索结果 | 每次都得调工具一条条处理 | CLM 论文已做（`compact_turns` 辅助函数调用 37 次）[N]；RLM 也覆盖 |
| ⑤ 多 agent 共享工作记忆 | 多仓库集群 | 只能发消息或查共享库 | CLM 论文已做（24 小时集群）[N]，而且很吃资源 |

### 2.4 CLM 天然吃亏的任务

- **以后才用得上的细节**：删了就找不回来，而记忆系统的存档能找回。第三轮验证的"延迟相关"就落在这一类。
- **跨会话的海量记忆**：上下文装不下。
- **弱模型零样本**：CLM 论文里 9B 模型的零样本结论在两处互相矛盾 [N]，说明 CLM 依赖强模型或训练过的模型。
- **安全**：可写的上下文是注入内容跨轮持久化的新通道。作者自己列为未来工作 [N]；角色头可以从工具输出里伪造，本仓库已复现 [R]。

## 3. 怎么从候选里选出这三个

### 3.1 调研工作流（2026-10-03）

- **规模**：21 个子 agent，只读文件、搜索摘要，不调模型做测试，耗时约 75 分钟。子 agent 合计约 208 万 token（工作流自报的口径）。
- **流程**：
  1. **读**：3 个读者分别整理 CLM 的机制和代码、竞品与已被占的领域、我们的资源与约束。
  2. **提**：4 个提案者各从一个角度提 3–5 个候选，共 12 个。四个角度是：
     - 机制优先：从 CLM 独有的操作出发；
     - 失败优先：从记忆系统和压缩已有记录的失败出发；
     - 资源优先：从我们现在能便宜跑的实验出发；
     - 反直觉优先：从文献冲突和"常识说没问题"的地方出发。
  3. **合并**：去重成 6 个。
  4. **审查**：每个候选配 2 个审查。
     - 撞车检索：网络搜索，结论都是 [S]；
     - 对抗批评：优势是不是 CLM 结构上独有、传统 harness 加一个工具能不能追平、可行性、成本、致命缺陷。
  5. **综合**：选出三个，把批评意见补进去，写成完整设计。
- **原始输出**：[records/clm_entry_points_workflow_2026-10-03.json](records/clm_entry_points_workflow_2026-10-03.json)。工作流里的编号和本文的对应关系：C1+C2 → E1，C3 → E2，C4+C5+C6 → E3。

| C4 | 没有线索的延迟约束 | 失败、资源、反直觉 | 部分 | 否 | 2 | 4 | 并成 **E3** |

### 3.3 元结论：一个接口，三把钥匙

每个候选的批评意见都认为，给传统 harness 加一个工具就能追平 CLM。这个判断是对的，但三个切入口需要的工具各不相同：

| 切入口 | 匹配基线（传统 harness + 一个工具） | CLM 剩下的余量 |
|---|---|---|
| E1 迟到的按属性更正 | 保留原始日志 + 代码查询 + 把更正后的视图追加到末尾（Scroll/RLM 式） | 原地修掉已经写进上下文的派生物 |
| E2 被拒之后的手术 | 被拒时触发清理：规则钩子，或带 redact 工具的清理模型 | 执行模型自己找到语义上连带的错误 |
| E3 会被撤销的前瞻约束 | 尾部可编辑的钉子或草稿区（PIN，或 Letta 式的块） | 钉子能改、能清理；历史能不按 FIFO 删（去噪） |

所以 CLM 的价值不在任何单独一格，而在于"一个接口覆盖三格"，外加一份因为什么都能改而付出的代价清单。即使三格的余量全是零，结论也可以发表：自编辑上下文相对已部署系统的优势是真的，但每一项都能被一个设计好的工具追平。

### 3.4 核实（2026-10-04）

- **代码**：§2.2 列出的行号全部复核过 [R]。
- **我们自己的数据**：
  - **子 agent 用量**：本会话 230 个只用 Read/Write 的 Haiku 题目类子 agent，按请求去重后，中位 4 次调用、约 14.8 万缓存读取（p10 10.9 万，p90 26 万）[R]。本文的成本都按每个子 agent 约 15 万估算。

## 4. E1：迟到的、按属性划范围的更正（工作流 C1+C2）

### 4.1 一句话 insight

例子：第 30 步来一条更正，说"第 10–40 步由 EDGE-4 扫描的入库，SKU 都记早了一个字母"。更正的范围是按一个事先没人想到会有用的属性划的。要答对，三样缺一不可：

1. 原始属性（这里是扫描来源）还在；
2. 有能执行的批量改写；
3. 已经写进上下文的派生物被修掉：自己做的盘点、STATE 面板、旧推理。

现有方案各缺一样（§4.3、§4.4），CLM 是唯一把三样放进同一个可执行介质的范式。

但 CLM 最省钱的"读完就压"，最先删掉的正是这些审计字段，压过之后它就落进了显式状态的失败模式。这是主线"到达时写入"的对偶：迟到的更正能不能用上，取决于信息到达时有没有被删掉。

### 4.2 CLM 的能力和匹配基线

- **CLM 的能力**：
  - 一条 python 命令，就能按"属性 × 步号窗"在任意多轮里定位并原地改值，或者做行内的作废标注；
  - 从改好的证据重算自己做的盘点；
  - 改掉旧推理里引用旧标签的句子；
  - 编辑成本和受影响的记录数 k 无关。
- **证据可以一直留着**：原始证据（包括说明书称为"操作元数据"的字段）可以一直留在上下文里，也可以先 `cp` 存档。
- **边界**：system 和任务说明受保护。能改的是证据和派生物，规则本身改不了。
- **匹配基线**：下面三种都同时拿到了"属性 + 算子"。
  - RAW+CODE-APPEND：代码算出更正后的视图，追加到末尾，原文不动（Scroll/RLM 式）；
  - RO-CODE-PERSIST：日志只读，代码把视图写到磁盘，每次决策重读；
  - EVENT-SOURCED：每轮从日志重新投影状态面板。
- **CLM 的余量**：相对这三种只多一项，就是原地修掉已经写进上下文的派生物。E1 要测的就是这一项有多大。

### 4.3 为什么记忆系统做不好

- **抽取式记忆**（Mem0、A-MEM、检索记忆）。以下机制描述是常识推断，docs 里没有这两个系统的专门条目：
  - 抽取时，source、batch 这类字段多半被当作元数据丢掉，划范围的条件就无从判断；
  - 即使字段还在，也要逐条做 k 次 UPDATE；
  - 决策时检索取回的，恰恰是标签已经错了的那些条目。
- **外部证据** [S]：
  - *Revoked but Still Authoritative*（2609.08258，已复核）：Graphiti/Zep、mem0、langmem、cognee 默认都不执行撤销，被撤销的事实排在替代它的事实前面，导致 agent 做出不安全动作；
  - TEPA（2608.07429，已复核）：完全反转时，只追加和后写覆盖的记忆都只有 0.210，低于不用记忆的 0.309；
  - 取代层（Temporal Validity，2606.26511）只处理"新值换旧值"，不处理按属性划出的一类事实。
- **MemGPT/Letta**：core 块里可以写一条规则"EDGE-4 的标签都早一个字母"，但历史里的值还是错的，之后每次读取都要在脑中重套这条规则。这属于读取时补救，本仓库测到它基本无效：CHECK 0/12、FACT 0/12 [P]。一工具版本（`bulk_update(filter, transform)` 加逐字存档）可以追平，前提是写入时没把元数据丢掉。
- **有界的自写笔记**：Supersede 在 LongMemEval-KU 上，完整上下文是 82/91/92，300 字符笔记是 63/64/77，给更多笔记空间也补不回来 [R]。

### 4.4 为什么 harness 做不好

- **定时摘要和压缩**：划范围用的字段被压掉，固化下来的是一张错的货架图。*Lost in Compaction*（2608.11242）测得压缩器平均只保留 17% 的会话约束 [S，已复核]；从业者也报告过压缩"保留结论、丢掉来源"[S]。
- **固定工具派**（SelfCompact、ACM、Context-Folding、Sculptor、ContextPilot）：没有"改写第 k 轮里的一个字段"这种操作。ACM 能把原文查回来，但查回来的仍是错值。
- **显式状态**：更正到来之前，错值已经整合进状态，历史被丢弃，schema 里又没有来源字段，没有东西可以拿来重算。这和第三轮验证里"无对应字段 0/24"是同一个结构 [R]。
- **不管理的完整历史**：证据都在，但每次决策都要在脑中重放一遍更正。短上下文下历史很稳（ig 24/24、vdepth 18/20 [P]），所以它只应该在 k 大、距离远、元数据密的格子里吃亏。
- **保留日志 + 代码查询**（Scroll [R 代码 / S 数字]、RLM [R]）：最强的对手，能现场重算；但改不了已经打印进上下文的旧视图，也改不了自己的旧推理。旧视图留在上下文里会不会导致错误，决定了 CLM 的余量有多大。唯一的外部线索是 In-Place Feedback（2510.00777）[S]：专家原地修改模型上一版回答、剪掉依赖段，比追加式的多轮反馈更可靠。但那是人来改、单轮推理，不是 agent 改自己的长程上下文。

### 4.5 假设（预注册）

| 编号 | 假设 | 判据 |
|---|---|---|
| E1-a | **CLM 独有的余量**：在"派生物污染"格（上下文里有模板写的、带旧标签的盘点快照和推理行），CLM-EDIT 比 RAW+CODE-APPEND 至少多对 2/12 | 差距 ≤ 1/6 即判定 CLM 在这一格没有独有优势，课题改为"保留原始证据 + 代码重算" |
| E1-b | **k 的剂量效应**：划范围的条件是元数据字段时，RAW 的正确率随 k∈{1,4,16} 单调下降，代码类条件基本持平 | 用 NO-CORR（同样的日志，不发更正）作基础难度锚点 |
| E1-c | **CLM 不该赢的对照格**：k=1、条件就是键本身（等价于值替换）时，各条件差距 ≤ 1/12 | 若 CLM 仍大幅领先，说明优势来自上下文变短之类的别的因素 |
| E1-d | **余量来自污染**：无污染时 RAW+CODE-APPEND ≈ CLM-EDIT；有污染时，前者的错误能在错误账本里追溯到旧快照（stale 类），后者不能 | — |
| E1-e | **隐藏条件**：通知只说"4 号码头的扫描枪上周校准错了"，模型要从记录的共现里推出 dock=4 ↔ source=EDGE-4 | 所有条件都会下降，但保留原始属性的条件下降得少 |
| E1-f | **条件字段随机**：每个种子从 `_meta` 的类别字段里随机挑一个作划范围的条件，固定 schema 事先猜不到 | STATE+预设来源字段只作天花板参考，不算发现 |
| E1-g | **CLM 应该输**：通知与证据矛盾时（裁决规则事先写明，配规则读者），覆盖式改写的 CLM-EDIT 识破率低于标注式的 CLM-ANNOT 和 RAW | — |
| E1-h | **压缩 × 可更正性的前沿**（闭环阶段）：迫使 CLM 在更正到达前就压缩（CLM-3K）且不存档时，属性存活率和更正后正确率都降到 STATE 的水平；允许 `cp` 存档时恢复 | 用同样压缩日程的非 CLM 摘要（SUM75）作对照，区分问题出在"压缩"还是出在"CLM" |

### 4.6 CLM 应该输或打平的地方

- **k=1 的值替换**：应该打平（E1-c）。短上下文下历史本来就稳。
- **没有派生物污染**：三个匹配基线应该打平；预设了来源字段的 STATE+src 应该打平或更好。
- **更正本身是错的**：覆盖式改写会销毁能揭穿它的证据，应该输给 RAW 和标注式（E1-g）。CLM 的 prompt 本身就叫模型把"被取代的笔记"换成摘要（`prompts.yaml` 第 22–24 行 [R]），默认倾向是覆盖而不是标注。裁决规则必须事先写清楚，这是 L2 的教训：那里历史 agent 被判错，是因为通知本身自相矛盾 [R]。
- **CLM 自己先压缩过**："读完就压"最先删掉审计字段，更正到达时已经无从重算，应该退到 STATE 的水平、低于 RAW（E1-h）。
- **失败的位置**：CLM 的失败应该出在写入上（编辑脚本漏改或误改，用与 oracle 的 diff 算精确率和召回率），而不是出在读取上。

### 4.7 实验设计

**第 0 步（不调模型）**：

- 在 `state_study/` 下新写一个"函数式更正"生成器，复用 `wh_env` 的 `generate`、`render`、`_meta`：
  - 让一个随机选中的元数据字段真正携带信息；
  - 第 c≈30 步发更正；
  - 提高入库密度，让 k 能取到 16（必要时 32–64）；
  - 拒绝采样保证两点：被改标签的托盘在更正前没被拣出，这样"只改标签、货物不变"的重放语义是唯一的；更正后第一个相关的出库或问答，正确答案会因为更正而改变。
- 只写一条重放规则：重标这些入库记录，再按事件重新投影货架图。规则读者和 oracle 共用这一条；k=1 时它和值替换完全一致。
- 规则读者测试和一致性检查（吸取 `dr_coherence.py` 的教训，自写，不复制）放进 `state_study/tests`。
- 派生物污染模板：在第 15、25 步插入模板写的 INVENTORY 快照和几行带旧标签的理由。这些由我们的模板生成，不是别的模型写的推理。
- 新写 ORACLE-EDIT。`render.py` 的 `tomb_inline`/`delete` 只接受 `warehouse.py` 的 Scenario，而且按 `superseded_by` 做值取代，不能直接用 [R]。
- 两段式驱动器，三个切入口共用，见 §7.4。

**第 1 步（静态题目，子 agent）**：

- **首批条件**：NO-CORR、RAW、RAW+CODE-APPEND、CLM-EDIT、ORACLE-EDIT。
- **第二批条件**：
  - RAW+PIN：只能追加一段文字更正，不能写代码，用来区分有没有代码；

**第 2 步（闭环，第 1 步测出余量才做）**：给 `wh_env` 加 CORR 条件，用检查点式驱动器在第 15、25 步施加压缩压力。比较 BASE、CLM-free、CLM-3K（不存档）、CLM-3K+archive、SUM75、RET。

### 4.11 风险与止损

- **天花板**：强模型可能在 RAW 上直接把更正套对。对策是调 k、距离、元数据密度三个旋钮；k=64 仍分不开就放弃。
- **余量为零**：CODE-APPEND 和 CLM-EDIT 相差 ≤ 1/6 时，不再宣称 CLM 独有。
- **构造性的质疑**：`source` 现在是纯噪声（`wh_env.py` 的 `_meta` 随机生成 [R]），一旦让它承载信息，就不再是"按设计是噪声"。所以划范围的字段每个种子随机挑，STATE 的地板不作为发现。
- **真值歧义**：如果更正前已经按错误标签拣过货，正确答案就有歧义。用拒绝采样排除这种情况，重放规则只有一条。
- **稻草人质疑**：MEM 基线是我们自己搭的。抽取给到 oracle 级，并写明这对 MEM 有利；接入真实的 Mem0/A-MEM 需要网络和密钥。
- **撞车**：MemoRepair、Rollback Repair、Matrix、MemTX、TEPA 都只看过摘要 [S]。定位为"没有预设来源记录、在活跃上下文里、由模型写程序重算"，再加上压缩 × 可更正性的前沿。作者删掉了 `ctx_metadata`、`ctx_archive` 两个开关 [R]，说明他们可能碰过这一块。
- **安全**：要执行模型写的脚本，必须限制在临时目录里、只读写一个文件、设超时。
- **领域单一**：第二个领域可以用 ALFWorld 的"某次观察的传感器有误"（`alfworld_facts.py`），或日志分析里"某个时间窗的日志重复"。

### 4.12 最接近的工作与区别

- **最接近的工作**（都是 [S]）：MemoRepair（2605.07242，已复核）、Dependency-Guided Rollback Repair（2608.10502）、Matrix（2608.12761）、*Revoked but Still Authoritative*（2609.08258，已复核）、MemSecBench（2607.27080）、TEPA（2608.07429，已复核）、Temporal Validity（2606.26511、2608.20685）、STALE（2605.06527）、PlanFence（2609.03340，已复核）、StateAuditor（2608.01619）、In-Place Feedback（2510.00777）。另外还有 Scroll（2608.21690），以及 CLM 自己 ContextBench 里的 Log Triage 和 KV Store。
- **不能当作新贡献的**："按来源作废并重算"，以及"记忆系统做不好撤销"。MemoRepair 把前者叫作"级联更新问题"：在来源记录完整的前提下，它把失效记忆的暴露率从 69.8–94.3% 降到 0%（已复核）。
- **这些工作的三个共同前提**：
  1. 写入时就记录了工程化的来源图或账本；
  2. 记忆放在外部的持久存储里；
  3. 由确定性的算子沿依赖边修复。
- **E1 的区别**：
  1. 划范围的条件是没人预见到的原始属性，没有来源图，由模型在活跃上下文里自己写程序；
  2. 做 k 的剂量曲线，并设值替换的对照格；
  3. 用最强的代码基线（Scroll 式追加视图）测"原地修改 vs 追加"的余量，而不是拿弱基线比；
  4. 测 CLM 自身"压缩激进程度 vs 可更正性"的前沿。
- **来自 C2 的保留部分**："派生结论的真值维护"现象已被 PlanFence（30/30 个工作流照旧执行过时计划，已复核）和 StateAuditor（状态解析 91%、行为适应 32%）占了 [S]。只保留"派生物污染"这个因子，用来区分字面依赖和语义依赖。

## 5. E2：被拒之后的上下文手术（工作流 C3）

### 5.1 一句话 insight

文献里对"自己的失败留不留"有三派说法 [S]：

| 主张 | 来源 | 证据 |
|---|---|---|
| 把错误留着 | Manus 工程博客 | 工程经验 |
| 清空重来 | *Why Retrying Fails*（2605.08563，已复核） | SWE-bench Verified 上拟合出污染比 ε1/ε0 = 7.1 |
| 改写失败调用的原文 | *Feedback That Backfires*（2608.23651，已复核） | 在 135M–1.7B 的小模型上，失败调用的原文造成 83% 的伤害；改写成运行时生成的描述，能去掉 76% |

三派看似冲突，其实各自测的是同一段失败文本的不同成分，而且都只能整段处置。

在不能重置、错误之前的信息还要继续用的环境里，正确做法是外科手术：留下世界给的拒绝反馈和还要用的观察，删掉或标注自己写错的东西。

可以检测到的错误，有一半能交给规则钩子，因为拒绝原因点名了货架。但被拒只暴露根上的那个错误信念，和它成对的沉默错误在字面上不提那个货架。例如传感器把 A 报在 12 号，实际在 13 号：被拒暴露的是"13 号被占"，没暴露的是"12 号其实空着"。只有懂推导的编辑者找得到后一半。CLM 不用加组件，执行模型自己就是这个编辑者；也正因为是自己改自己，它可能自我洗白。

E2 是 [idea_bank.md](idea_bank.md) B4"Forget the trace, keep the lesson"的重启和扩展。B4 原定在主线 H2 做完之后重启，**重启要用户确认**。

### 5.2 CLM 的能力和匹配基线

- **CLM 能改哪些文本**：能在比一轮更细的粒度上改写自己写过的文本，并区分两类：
  - 模型自己的：推理、断言、失败命令的原文、写错的 STATE 行、自己的盘点；
  - 世界给的：ACTION REJECTED、观察。

  `render_editable` 把 reasoning、内容和发出的命令都渲染进可编辑文本 [R]。
- **可用的操作**：原地改对（SURGICAL）、删掉错误推理（DELETE-SPAN）、就地标注撤回、把失败命令原文换成一句描述（REWRITE-SURFACE）、删掉失败尝试只留教训（LESSON）。都可以用一条 python 正则批量完成。
- **CLM 的默认行为已经指向这里**：
  - prompt 要求把 dead ends 换成摘要 [R]，所以它默认就会对失败做 LESSON 式处置，关键是摘要里有没有留下世界的反馈；
  - 回滚账本的存在说明，抹掉"刚试过什么"会让模型重发同一条命令、陷入死循环 [R]；
  - idea_bank A6 的"原地打转"也是同一种失败。
- **匹配基线**：
  - HOOK（规则钩子）：收到"shelf s is occupied"，就删掉或标注断言 s 为空的句子，并改写失败命令的原文。`wh_env` 的拒绝原因点名了货架（`wh_env.py:95`、`104` [R]），钩子不到 30 行；
  - JANITOR（清理模型）：每次被拒后起一次同档模型的清理调用，配一个固定的 `redact(turn, span, replacement)` 工具和一行提示。
- **CLM 的余量**：相对 HOOK 在语义上连带的错误；相对 JANITOR 预计打平。打平时的结论是"需要一个 LLM 级的编辑者"，而 CLM 让执行模型自己就是这个编辑者。三格里只有这一格的匹配基线本身也必须改写历史。

### 5.3 为什么记忆系统和 harness 做不好

- **记忆系统**（Mem0、MemGPT、Reflexion 式教训库）：改的是上下文之外的存储或 core 块，活跃上下文里的错话原样还在。
  - *When Memory Updates but Behavior Does Not*（2608.01619）：状态解析 91%，行为适应只有 32% [S]；
  - 自写存储也不会自己变干净：*Self-Cleaning and Captured Anyway*（2609.25052）研究 agent 把结论写进自己的存储再取回的闭环 [S，存在已复核；"前沿规模下 capture 0.850、claude-sonnet-4.5 在 20/20 个种子上被捕获"这些数字未复核]。
- **显式状态**：污染的载体从轨迹换成了写错的状态，历史又被丢掉，没有证据可以拿来纠正。本仓库的重新统计 [R]：
  - Haiku T=200，错误信念中位持续 24 步，46 处里有 15 处到结束都没修好；
  - ACTION REJECTED 点名货架之后，下一次补丁修好信念的只有 8/78；
  - 错误来源中，51/70 是动作错了，19/70 是动作对、补丁写错。
- **只追加**（Manus 式）：正确事实能补上，但错话仍以 assistant 身份留在上下文里。本仓库的错误成串比 P(错|上一步错)/P(错|上一步对)，ReAct 约 6，有状态的 runtime 13–14 [R]。这个比值混有难度差异，见 §5.9。
- **清空重来**：去掉了先例，也毁掉了信息。仓库这类环境的库存只能从历史推出来，重来就等于丢掉状态。PivoARL（2607.03702）能复用正确的前缀，但要靠 RL，还要求环境能回到关键状态 [S]。
- **定时摘要**：时机由 harness 决定，往往离错误很远；摘要器还会把错误结论当成干净的事实写进摘要。
- **隐藏、软删除**（Sculptor、ContextPilot）：以段为单位，没法在同一轮里只删错话、留下拒绝反馈。
- **规则钩子**：只能修字面上命中的根，修不了成对的沉默错误。

### 5.5 CLM 应该输或打平的地方

- **反馈或更正本身是错的**：删改会销毁能揭穿它的证据（E2-g）。
- **自我洗白**：改写观察去迎合错误信念，或删掉证明自己错了的拒绝（E2-f）。
- **字面上能定位的错误**：HOOK 就能打平，CLM 还多花一次编辑。
- **强模型**：Sonnet 的错误信念中位只持续 1 步 [R]，预计打平。但 *Self-Cleaning* 报告前沿模型照样被捕获 [S]，方向不确定，所以当作待测项，不预设效应为零。
- **推理固化**：`render_editable` 把 reasoning 并进了可编辑文本 [R]。第一次编辑之后，本来可以被剥掉的推理会作为可见文本留下来，可能加厚自我条件化的载体。子 agent 下测不了。
- **作者身份这一维**：题目类测试里，子 agent 是把整个前缀当文件读进来的，标成 assistant 的轮次对它只是工具结果，所以测不出作者身份的效应。要等有 API 密钥后用多轮 messages 来测。*Self-Correction Illusion*（2606.05976，已复核）显示，错误内容逐字不变、只把角色从 thought 改成外部来源，明确纠错率就提高 23–93 个百分点，所以这一维不能忽略。

### 5.6 实验设计

**阶段 0（零成本，只运行、只读）**：

- **数据**：scratchpad 里约 2000 个 delayed-relevance 轨迹文件。统计口径沿用 `dr_persistence.py`、`dr_adoption.py`、`dr_common.py`。脚本自写，运行时导入对方的环境，不复制。
- **统计**：
  1. 用回合内置换零假设和带回合随机效应的 logistic 回归，重算错误成串比；
  2. 把同一事件的重答和下一个新事件分开；
  3. 被拒后的下一次尝试与失败原文之间的编辑距离和逐字重复率，按 runtime × 模型分开（检验 E2-0 和载体迁移）；
  4. 有状态 runtime 在被拒那一步，除了被点名的货架，信念里还有几处错。这是成对错误的自然基础率，决定阶段 1 的任务是否自然。
- 正则判定要人工抽查。

**阶段 1（静态模板题，子 agent）**：

- **给 `wh_env` 加一个扰动开关**：
  - 第 t 步传感器出错：确认消息报"已放 12 号"，实际放在 13 号；
  - 几步后 agent 往 13 号存货被拒，拒绝消息点名占位的托盘；
  - 正确的重答是存到 12 号（A 在 13 号，12 号其实空着）。只修了根的 agent 会存到 14 号，这种错误物理上可行、不会被拒，是静默的。
- **前缀**：只有实验者写的动作串、模板化的理由行和拒绝反馈，没有任何模型写的推理。
- **首批的臂**：ORIG（KEEP）、HOOK、ORACLE-PROPAGATE、CLM-SELF。CLM-SELF 走两段式：编辑子 agent 写脚本，驱动器执行，再由回答子 agent 作答。
- **第二批的臂**：
  - APPEND-CORR：在尾部追加正确事实，只补信息；
  - JANITOR；
  - ERASE-ALL、ERASE-SELF、LESSON、RESTART；
  - 位置匹配和长度匹配两组对照；
  - 错误拒绝臂。
- **决策点**：t+1（重答被拒的事件，主指标），以及 t+k（之后再次依赖沉默那一半的入库）。
- **指标**：
  - 决策正确率；
  - 编辑后残留的派生错误断言数，由规则读者核对；
  - 重复同一错误动作的比例；
  - 世界证据被删的次数、观察被篡改的次数，与受保护的"世界文本"片段做 diff；
  - CLM-SELF 实际选择了哪类编辑。

**阶段 2（闭环，推迟）**：检查点式驱动器，扰动步之后 12 步每步起一个新子 agent，其余步用规则读者给出的动作。臂：只追加、CLM-lite、JANITOR、SKILL.state-lite、清空重来、错误拒绝。规模：Haiku × 6 个种子。

### 5.7 最小 pilot 与判读

- **先做阶段 0**，不花 token。满足任一条就止损：控制难度差异后，错误成串比 < 2；有状态 runtime 的重复率不高于 ReAct。
- **阶段 0 通过后跑 pilot**：Haiku，12 个种子 × 4 个臂（ORIG、HOOK、ORACLE-PROPAGATE、CLM-SELF），主决策点是 t+1 的重答，共 48 个回答子 agent；另加 12 个 CLM-SELF 编辑子 agent，合计 60 个。
- **决定性的比较是 CLM-SELF 对 HOOK**：
  - 相差 < 3/12：CLM 在这一格没有独有余量，结论改为"需要上下文卫生，但规则钩子就够了"；
  - ORIG 与 ORACLE 也分不开：成对错误在这个设定里不构成瓶颈，止损。
- 模板前缀里没有别的模型写的推理，可以先拿 2 题试 Sonnet。被拦就只报 Haiku，**不改写题目去绕开**。

### 5.9 风险与止损

- **先例通道可能根本不存在**：有状态 runtime 不保留 assistant 的历史，错误成串比却是 13–14，比 ReAct 的约 6 还高 [R]。这更像是信息通道或难度造成的，由阶段 0 来判定。
- **基础率低**：`wh_env` 的沙盒回合里，Haiku 50 步只错 1 步，一次都没被拒过 [R]，只能人为植入错误。植入的错误以文件形式呈现时，并不是模型"自己写的"，自我条件化的前提很弱。所以主指标改用信息通道（沉默的那一半有没有残留），作者身份留到 API 阶段。
- **撞车密集** [S]：
  - *Feedback That Backfires*（小模型，只看表面形式这一个成分）；
  - *Self-Correction Illusion*（单轮，只看作者身份这一个成分）；
  - *Why Retrying Fails*（假设任务可以重置）；
  - *When Can Agents Forget Their Reasoning?*（2609.29875，已复核，2026-09-24 才提交）：在线删除历史推理块，保留动作、工具调用和观察；在 260 个 WorkBuddyBench 任务上，平均奖励从 0.699 升到 0.718，缓存读取 token 减少 33.3%。出发点是效率，不是错误污染；
  - *Self-Cleaning*、PivoARL。

  新意只能落在四处：不可重置的闭环、成对错误、谁来做手术、自我洗白。作者删掉的 `shadow_progress_guard`、`research_ledger` 开关 [R] 是撞车预警。
- **与主线的张力**：主线认为到达时的写入决定成败，这一格做的是事后修复。可以这样协调：拒绝反馈本身也是一次"到达"，它的写入要传播到所有决策会读的地方，而 8/78 的采纳率说明这正是短板。
- **测量限制**：子 agent 测量的限制要标明。Sonnet 遇到模板理由行可能被拦，被拦就只报 Haiku 和只含动作的前缀，不改写题目绕开。统一用两段式（子 agent 只 Read/Write，脚本由驱动器执行），不给子 agent Bash。

## 6. E3：没有线索、还会被撤销的前瞻约束（工作流 C4+C5+C6）

### 6.1 一句话 insight

有一类约束，到达时不需要任何动作，之后也不会出现检索线索，比如第 8 步的隔离通知。对它们来说，"可恢复的删除"（ACM、ContextPilot、Sculptor、VISTA、Scroll 的各种存档）和检索记忆在结构上都等于删除，因为没人想得到去查。能走通的只有两条路：

1. **到达时绑定**：把约束写到决策一定会读的地方。钉一条笔记就是 12/12 [P]。
2. **去噪**：删掉噪声，看历史能不能自己整合。现在只知道两端：近距离、短上下文时历史 24/24 [P]；相隔 40 步、约 2 万 token 时 0/24 [R]。只减 token、不减步数会怎样，还没人测过。

只追加的钉子，在约束被撤销、改范围或越积越多时会坏：

- TEPA：完全反转时，只追加的记忆是 0.210，低于不用记忆的 0.309（已复核）；
- Constraint Pinning 出过生产事故：钉子吃光了渲染预算 [S]。

所以负责绑定的一方，也必须负责清理。CLM 让执行模型同时负责绑定和清理，两条路都能走。代价是它自己的压缩成了第三条丢失通道：最旧的一轮最先被删，而提示原文写的就是 "delete stale turns/outputs" [R]。

这一格和主线"到达时绑定"贴得最近。

### 6.2 CLM 的能力和匹配基线

- **到达时写入**：约束到达那一步，看得到任务说明的执行模型自己决定在可编辑区的什么位置、以什么形式写：
  - 原样保留；
  - 在尾部写一行 PIN 或 `## STATE`；
  - 编进自己维护的空位表或计分板，标 BLOCKED，写明解除条件；
  - 读完就压；
  - 先 `cp` 再删。

  动作和编辑可以放在同一条命令里。fit 门下，编辑后变大也接受，只要不超预算 [R]。
- **处理撤销**：约束被撤销或改范围时，可以原地删掉或改写旧的绑定。`wh_env` 现在的 PIN 只增不减（`wh_env.py:296`，`st["pins"] += shown` [R]），做不到这一点。
- **非 FIFO 的选择性删除**：删掉新近的遥测和审计噪声，留下最旧的那条通知。FIFO 截断、按年龄遮蔽、整段摘要都做不到，只有设计者事先写好的字段黑名单能做到。
- **观测价值**：`parse_back` 前后的 diff 把"这条以后没用"的判断变成可观测的事件，可以用来测中介变量："约束有没有以有效的形式活到决策"。
- **两处事实修正**（来自批评意见）：
  - system 和任务说明受保护，所以"改写说明书正文"不是 CLM 的能力；
  - 预算为 0 时，`may_grow` 拒绝任何变大的编辑 [R]，所以"无预算"条件要改用 fit 门加一个很大的 limit（例如 10 倍）。
- **匹配基线**：
  - PIN：只追加，在尾部重放；
  - SCRATCH：尾部自由格式的块加 `str_replace`，不能删历史，相当于把 Letta 的 core 块挪到尾部。

  CLM 相对 SCRATCH 只多一种能力：删改原始历史。好处是预算余量和去噪，代价是静默的误差。

### 6.3 为什么记忆系统做不好

- **检索式记忆**（Mem0、A-MEM、RAG）：决策时需要什么，写不成查询。
  - 第 48 步只是一托普通的入库，文本上和第 8 步的 `facility_notice` 没有关联 [R]；
  - 本仓库测得通用回看指令 0/12，改写成占用事实也是 0/12 [P]；
  - TriggerBench 发现前瞻记忆随上下文长度下降 [S]；
  - Mem0 式"抽取后写入"由一个独立的抽取 prompt 决定，它看不到任务程序。连历史 agent 自己都把这条通知判成了"管理性元数据，Wait" [R]。
- **MemGPT/Letta**：
  - core 块由模型自己写、系统保证持久，在准确率上可能是强基线；
  - 但它默认放在 prompt 前部，每次编辑都打断缓存。delayed-relevance 实测，同样的内容，可变状态放前面的成本是放后面的 5.7 倍 [R]；
  - 历史队列由系统按 FIFO 管理，模型删不了噪声，去噪这条路走不通。
- **只追加的记忆和钉子**：
  - TEPA（2608.07429，已复核）：完全反转时只追加和后写覆盖都是 0.210，不用记忆是 0.309，TEPA 自己是 0.950；
  - *When Stale Constraints Go Unchecked*（2608.25553）：继承了已撤回约束的 agent，约 75% 照旧执行 [S]。
- **显式状态**：SKILL.state 无对应字段时 0/24，有自由字段时 10/24，只有预设了专门字段才 24/24 [R]。PIS（2609.01272）把意图的生命周期写成代码，但类型由人定 [S]。

### 6.4 为什么 harness 做不好

- **定时摘要和观察遮蔽**：在预算用到 75–90% 时由一个固定的 prompt 判断什么相关，这时离约束到达已经很远。外部证据（[S]，均已复核）：
  - *Lost in Compaction*（2608.11242）：压缩器平均只保留 17% 的会话约束；外挂一个专门抽取约束的模块，能把保留率提到 90% 以上；
  - *Governance Decay*（2606.22528）：在 1,323 个回合里，压缩后违规率从 0% 升到 30%，部分模型到 59%；Constraint Pinning 只钉约 47 token 的策略原文，就把违规率压回 0%；
  - *Compaction Cliff*（2608.22752）：Claude Code 的 /compact（Sonnet 4.6）一轮后安全规则存活 53%，五轮后 10%；
  - *AI Guardrail Survival*（2608.11392）："在场不等于有效"。压缩没把规则整条删掉时，常留下一个看起来像规则、却不起作用的残留；残留的规则导致违禁动作多出 34 和 57 个百分点。
- **固定工具派**（SelfCompact、ACM、ContextPilot、Sculptor）：模型能决定什么时候压，但只能整段或整轮地压、藏、卸载。可恢复不等于被留住：想不到去查时，存档再完整也取不回。
- **harness 钉子**：单条约束很有效，但只增不减。memnos issue #153 记录了一次生产事故：6 条钉住的约束共 10,040 字符，超过了 9,000 字符的渲染预算，召回的事实被挤成 0 条 [S]。
- **设计者写的字段黑名单**：能去噪，但要事先知道噪声长什么样。遇到没见过的事件类型（例如 `ops_bulletin`），只能全留或全丢。

### 6.5 假设

| 编号 | 假设 | 判据 |
|---|---|---|
| E3-0 | **门槛：自压缩下的存活**。在超预算（OVER）的压力下，让 Haiku 压缩第 20、35 步的 CLM 镜像；通知位于第 8 轮，是最旧的一轮。分别报告它以原文存活、以提炼形式存活、被删掉的比例 | 若 ≥ 90% 被删，CLM 在这一格的优势基本判死，降级为主线里"CLM 自压缩是一条丢失通道"的负结果 |
| E3-a | **中介是功能性存活**：决策正确率由"活到决策的文本是否仍能约束动作"决定。用规则读者判定：只读存活下来的文本，能否推出这条限制。原文虽在、却淹没在长上下文里的不算存活 | 这样，BASE 里通知 100% 在场、正确率却是 0/24 [R]，就不再是反例 |
| E3-b | **去噪是第二条路**（同时检验主线 H1"事件数而非 token 数"）：不做任何绑定，只把决策时的上下文去掉审计块和遥测，事件步数不变 | 预测历史 agent 的正确率显著升高。若不升，说明失败由步数或事件数决定，不由 token 数决定，CLM 的删除只省钱、不开新路。注意：`wh_env` 沙盒回合（约 7 千 token，带它自己的推理）仍在第 48 步违规，n=1 [R] |
| E3-c | **撤销是 PIN 的结构弱点**：m 条约束里有撤销或改范围时，在撤销后的第一个决策上，只追加的 PIN 出错（过度保守或自相冲突）显著多于 SCRATCH 和 CLM | 无撤销时三者打平（PIN 12/12 [P]） |

### 6.6 CLM 应该输或打平的地方

- **单条、不会撤销的约束**：CLM ≤ PIN（12/12 [P]）。这时 CLM 只是一个自己选位置的 PIN，还多了一条自压缩的丢失通道。
- **预算很紧时**：最旧的一轮（也就是通知）最先被删，CLM 低于 FULL 和 PIN。
- **到达时"读完就压"**：通知被当成噪声一起压掉。先例是历史 agent 把通知判成了元数据 [R]。
- **对比 SCRATCH**（Letta 式尾部可编辑块）：准确率应该打平，CLM 多出的只是能删历史带来的预算余量。
- **对比设计者写的字段黑名单**：在去噪这条路上应该打平。
- **可检索的格子**：检索和存档应该能追平（E3-f）。
- **最大的反面证据**：*Delivery, Not Storage*（2607.20972，已复核）的立场正好相反，认为这类工作记忆必须是 harness 的属性，不能交给 agent 选择。它的数据也支持这一点：即使预先给记忆库灌好内容，agent 在 114 轮里主动使用记忆的次数是 0；由 harness 按触发条件确定性注入，在每个配备注入的回合里都送达了，误触发为 0 [S]。这和本仓库 BASE 回合里 Haiku 对通知只回 `Wait({})` 一致。PIN 能到 12/12，是因为说明书明确要求"遇到规则或限制就钉住"[P]。所以 CLM 能不能**主动**在到达时绑定，是 E3 里最大的未知数。

### 6.7 实验设计

**第 0 步（不调模型）**：

- **写 ctxloop 驱动器**：在三格共用的两段式驱动器上加检查点模式。
  - 运行时导入 `wh_env` 的 `generate`、`expected`、`check`、`render`，以及 `render_editable`/`parse_back`；
  - 用 fit 门、可调的预算，给出 `[context: ~X/Y]` 读数和 OVER 提示（按 `env.py` 的语义改写文案并署名）；
  - 所有带预算的条件都给同样的读数和提醒，补上 CLM 论文缺的公平性消融 [N]。
- **内置的策略**：
  - FULL、SUM75；
  - RET（每步抽事实，标准库 BM25 取 top-k 放到尾部）、RET-RULES（Mem0 式，规则类记忆总是注入）；
  - ARCH（ACM 式的摘要、卸载、召回，自写，不复制）；
  - CORE（Letta 式前部块）、SCRATCH（尾部块 + `str_replace`，不能删历史）；
  - PIN、PIN-under-budget；
  - BLACKLIST（设计者写的字段删除规则）；
  - STATE（无对应字段）、PIS-lite（预设意图字段，只作天花板参考）；
  - CLM-lite。

  所有条件用同一个历史截断规则，不配确定性摘要器，免得把差距算到摘要器头上。
- **扩展 `wh_env`**：
  - 支持 m∈{1,3,6} 条通知；
  - 类型分静态（隔离、SKU 禁区、容量上限）和事件触发（到第 t 步解除、某货架发货后解除），可以带撤销或改范围；
  - 拒绝采样，保证每条约束恰好在指定的那一步第一次改变正确动作；
  - 每条规则配规则读者测试：会绑定的读者全对，不绑定的读者在决策步违规。
- **处置类别由规则读者判定**：
  - 只读结构化字段就能推出正确动作：编译；
  - 只出现在自由文本里：笔记；
  - 原通知逐字还在：原文；
  - 都不是：删除。

**阶段 1（静态题目）**：

1. 自压缩存活探针（E3-0、E3-a）；
2. 去噪探针（E3-b）；
3. 撤销探针（E3-c）：撤销那一步起一个编辑子 agent（PIN 只能追加，SCRATCH 只能改块，CLM 可以改整个可编辑区），撤销后的第一个决策步起一个回答子 agent。

**阶段 2（检查点式闭环）**：

- 普通步骤由规则读者生成模板化的动作串，不含推理文字；
- 只在到达步及其后 3 步、预算压力点、撤销步、决策步各起一个新的子 agent，读上下文文件、写一条命令，由驱动器执行并读回；
- 先跑 1 个种子冒烟、实测 token，再用 `wh_pilot.py audit` 核对；
- 最后用 3–4 个种子做逐步忠实的 CLM 复核，或者等有 API。

**指标**：

- 每条约束第一次起作用那一步的正确率。每回合只计第一个受约束影响的决策，或者在决策前把真实的货架状态重置给 agent，切断错误成串；
- 三种存活（原文、提炼、位置）加功能性存活；
- 到达账本：到达后 4 步内是原文保留、被提炼还是被删除；
- 过时钉子的数量；
- 成本按三种口径：token；带缓存的美元估计（用驱动器记录的上下文序列计算公共前缀，属示意）；CLM 的本地估计。

### 6.8 最小 pilot 与判读

两个静态探针都不需要先建闭环：

1. **自压缩存活**：
   - 用 `wh_env` 生成第 20、35 步的 CLM 镜像：CTX_TURN 格式，只含环境输出和模板化的动作串，通知原样留在第 8 轮，读数为 OVER；
   - 每题一个 Haiku 子 agent，Read 文件后 Write 一个压缩脚本，由驱动器执行；
   - 2 档预算（1.0×、0.5×）× 2 个时点 × 6 个种子 = 24 题；另加 6 题对照，通知已被提炼成尾部的一行 NOTE，看这一行能不能保住。共 30 题；
   - 由脚本做 diff，判定通知是原文保留、被提炼（以及提炼到了哪里），还是被删，再用规则读者判定功能性存活。
2. **去噪**：决策步的上下文渲染成三种版本：原样、去掉审计块、去掉审计块和遥测，都不做绑定。每种 8 个种子，共 24 题。

合计 54 个子 agent。判读：

- 探针 1 里第 8 轮被删 ≥ 90%：判死，降级为负结果；
- 探针 2 去噪后 ≥ 6/8：去噪是第二条路，进入撤销探针和闭环；
- 探针 2 去噪后仍 ≤ 1/8：主线 H1（事件数而非 token 数）得到支持，CLM 的删除在这一格只省钱。

### 6.10 风险与止损

- **最可能的结局**：单条约束时 CLM ≈ PIN，多条约束时 CLM ≈ SCRATCH。那样的结论是"绑定必须可编辑、可回收"，而不是"CLM 独有"。
- **止损**：撤销探针里 PIN 不比 SCRATCH 差（相差 < 2/8），说明撤销不是 PIN 的弱点。这条线就并入主线，作为"CLM 自压缩"的负结果。
- **主动编辑太少**：Haiku 可能几乎不主动编辑。CLM 论文里 9B 模型平均每题只编辑 1.4 次 [N]；*Delivery, Not Storage* 里主动使用记忆为 0 [S]。这时要加 `prompts.yaml` 的教学文案，会引入提示偏置，要如实报告。
- **检查点模拟的局限**：普通步骤用 oracle 动作，抹掉了漂移，也拆开了"动作和编辑在同一条命令里"这一点。结论只能标成"在决策点上忠实"，要用逐步回合复核。
- **撞车最密** [S]：
  - *Delivery, Not Storage*（2607.20972），结论相反；
  - *Compaction Cliff*、TEPA、*AI Guardrail Survival*、PM-Bench、TriggerBench、PIS；
  - Constraint Weakening（2608.24569）：交接时的压缩保留了约束的文字，却去掉了它的约束力 [S]；
  - "Triage"这个名字已被 *Compaction Cliff* 的 Knowledge Triage 用掉；
  - [clm_notes.md](clm_notes.md) §13.5 方向 1 就是这一条。作者删掉了 `ctx_archive` 和 `research_ledger` 两个开关 [R]，说明可能试过。
- **安全分类器**：检查点驱动器里，上一个子 agent 写的编辑命令可能让 Sonnet 被拦。先试 1–2 题，被拦就停，不改写题目绕开。
- **领域单一**：要用 ALFWorld 补。子 agent 测量的限制也要标明。

- **最接近的工作**（[S]）：
  - *Delivery, Not Storage*（最接近，结论相反）；
  - *Compaction Cliff*（2608.22752，harness 压缩下的存活曲线和按类型保留）；
  - *Lost in Compaction*、*Governance Decay*（含 Constraint Pinning）、*AI Guardrail Survival*；
  - TEPA（设计好的冲突键加撤销存档）；
  - *When Stale Constraints Go Unchecked*、PIS、Constraint Weakening；
  - PM-Bench、TriggerBench；
  - Self-GC（2607.00692）、*Learning What Not to Forget*（2606.20954）、*Just-in-Time Memory*（2609.27334）、VISTA（2606.30005）、TACO（2604.19572）；
  - CLM 的 Needle Retention：会告诉模型要留什么，和这里不同 [N]。
- **已经有人做过的成分**：压缩丢约束、存活随压缩轮数下降、钉子有效、撤销需要专门的机制。
- **还空着的组合**：
  1. 在同一个探针上，把"执行模型自己编辑上下文"作为自变量，正面比较检索记忆、定时摘要、固定工具、只追加的钉子和可编辑的草稿区；
  2. 把模型后来的自压缩，从"到达时没写下"中拆出来，作为独立的丢失通道，用 `parse_back` 的 diff 加功能性存活的规则读者作中介变量；
  3. 用"可检索 × 不可检索"的交叉，事先划出 CLM 应该赢和应该打平的格子；
  4. 去噪这条路（token 数 vs 事件数），直接接到主线 H1；
  5. 在没有设计冲突键的情况下（TEPA 设计了），检验撤销是不是只追加绑定的结构弱点。

## 7. 三格合成一篇

### 7.1 形态

暂定题目："*One interface, three keys: where self-editing context beats one-tool harnesses, and what it costs*"。

- **设计**：每格放一个匹配的"一工具基线"，再放一个三把钥匙都给的**并集基线**，也就是一套固定工具集，与 AgeMem、ACM"扩充工具集"的思路同类。
- **可证伪的整体预测**：
  1. 每个一工具基线只赢自己那一格，输另外两格；
  2. CLM 在三格都接近匹配基线；
  3. 如果并集基线也接近 CLM，CLM 的贡献就收缩为"不用事先设计工具集"。这时要再加一个留出格，检验工具集没预见到的操作。

### 7.2 通用性代价

每格各测一项 CLM 因为什么都能改而付出的代价：

| 切入口 | 代价 |
|---|---|
| E1 | 压缩把来源洗掉，迟到的更正无从重算 |
| E2 | 自我洗白：改观察去迎合错误信念，或删掉证据 |
| E3 | 自己的压缩把最旧的约束删掉 |

### 7.3 公平性消融

CLM 论文里只有 CLM 享有三项待遇：超预算前的提醒、纯编辑轮不计步数、超预算回滚后重试 [N]。我们把这三项也给所有基线，这正是论文缺的那组消融。

### 7.4 共用的基础设施：两段式驱动器

1. **编辑子 agent**：只许 Read 题目文件、Write 一个 python 脚本。
2. **驱动器**：在只含上下文文件副本的临时目录里执行这个脚本，用 AST 白名单、超时、只能读写这一个文件。执行后按 fit 规则验收，给出 `[context: ~X/Y]` 读数。渲染和读回用运行时导入的 `render_editable`/`parse_back`，不改 `clm/`。
3. **回答子 agent**：读编辑后的文件作答。

这个设计正好绕开"子 agent 改不了自己的对话"这个限制，也不用给子 agent Bash 权限，审计起来简单。另外三格还共用：检查点式闭环驱动器、`wh_env` 的生成器和规则读者框架、错误账本、盲化和审计。

### 7.5 和主线的关系

- **E3** 是"到达时绑定"在 CLM 里的延伸：负责绑定的一方也必须负责清理。
- **E1** 是它的对偶：迟到的更正能不能用上，取决于信息到达时没有删掉什么。
- **E2** 是主线 H2"写入误差会粘住"的第一个干预实验：拒绝反馈本身也是一次"到达"，而状态 agent 被点名之后只修好了 8/78 [R]。

这篇可以作为主线分析型论文的第二部分，也可以单独成篇。主线要不要改写，仍待用户决定。

## 8. 顺序、预算和需要用户做的事

### 8.1 建议顺序

|---|---|---|---|

**按约定，每一步启动子 agent 之前，都先向用户报跑什么、跑几个、预计用量，等确认后再跑。**

### 8.2 需要用户决定或提供的

1. **选方向**：从 E1、E2、E3 里选一个开始，或者三个都做、合成一篇。

## 10. 局限

- **全部是设计**：三个切入口都还没有任何数据。"预计"、"应该"都是预测，要用 pilot 检验。
- **文献只有摘要级证据**：14 篇用网络搜索复核过存在和关键数字（[related_work.md](related_work.md) §11），其余只有工作流子 agent 的搜索结论。原文一篇都没读（arxiv 被拦）。
- **评分是主观的**：insight、新颖性、可行性的 1–5 分来自批评 agent，只用于排序。
- **子 agent 测量的限制**：带着 Claude Code 的系统提示，温度不可控，输出 token 数不可靠；Sonnet 和 Opus 遇到别的模型写的推理会被安全分类器拦截。所有结果都要标成"子 agent 测量"。
- **成本是估算**：每个题目类子 agent 约 15 万缓存读取，是本会话 230 个子 agent 的中位数；闭环检查点和逐步 CLM 的成本是推算，没有实测。
