# 用真实数据造 KV 管理的 SFT 数据（2026-11-17 起）

背景和动机见 `docs/sft_v2_diagnosis.md`：SFT v2 学到的是固定模式，没有学会"什么时候换出、什么时候换回、换回哪页"。

## 和用户确定的原则（2026-11-17）

1. **训练不用任何合成数据**。T1 和其他合成数据（T1b、大海捞针）不进训练；T1 只保留作诊断评测，用来查有没有走捷径。
2. **每个动作都要有模型看得到的线索**：
   - 换出看压力：仪表盘显示 `free F | next page ≤ P`；
   - 换回看"问题和页标签是否对得上"。
3. **需要换回的地方，必须换回对应的页才能答对**，不能靠猜。
4. **不能有固定模式**：页长、预算、问题时机、换回次数和位置都要变化，用模式探针检验。
5. **`kv_out` 带模型写的页标签，每个动作配一句理由**。
   - 由 Qwen3-8B 自己写，写的时候只看学生当时看得到的东西；
   - 要有信息量，不能变成套话：检查内容特异性和句式集中度。
6. **合并多道题的段落进同一串页流可以接受**：文本、问题和答案都是真实的，只有排列由我们决定。

## 数据来源（都用训练集）

| 数据 | 官方文件 | 证据标注 | 云端取样 |
|---|---|---|---|
| HotpotQA（distractor） | `hotpot_train_v1.1.json`（ModelScope `OpenDataLab/HotpotQA`） | `supporting_facts` | 文件开头 25 MB |
| 2WikiMultihopQA | `train.json`（作者 Dropbox，`data_ids_april7.zip`） | `supporting_facts` | 文件开头 20 MB |
| MuSiQue | `musique_ans_v1.0_train.jsonl`（ModelScope `voidful/MuSiQue`） | `is_supporting` | 文件开头 12 MB |
| Qasper | `qasper-train-v0.3.json`（官方 S3） | `evidence` 段落 | 全部 888 篇 |

**过滤规则：**
- 丢掉"能猜"的题：是/否题，以及答案出现在问题里的题（如"A 还是 B？"）；
- 和评测集去重：
  - LongBench 的 `data.zip`：问题文本，以及按 "Passage N:" 和空行切出的段落文本；
  - 其他评测文件：问题文本；
  - 一篇文档只要有任何一段在评测集里出现过，整篇丢掉；
- Qasper 的证据如果是图表（"FLOAT SELECTED"），或者对不上原文段落，这道题跳过。

**在样本上的过滤结果：**

| 数据 | 原有问题 | 保留 | 主要丢弃原因 |
|---|---|---|---|
| HotpotQA | 3994 | 3459 | 答案在问题里 293，是/否 242 |
| 2Wiki | 4719 | 2240 | 是/否 1646，答案在问题里 833 |
| MuSiQue | 985 | 981 | — |
| Qasper | 1861 | 1568 | 是/否 286 |

MuSiQue 文件开头只有两跳的题，三跳、四跳的题在后面。

## 页流怎么构造（`data/qa_streams.py`）

- **Wiki 类数据**：2–8 道题（可以来自不同数据集）的段落放进一串页流。
  - 重复的段落只出现一次；
  - 60% 的页流完全打乱顺序，40% 按文档分成松散的块。
- **Qasper**：一篇论文按阅读顺序排列。
- **分页**：每页 1–3 个相邻段落，页长取决于原文。
- **提问时机**：
  - "问题先给"：在证据页到达之前提问；
  - "问题最后给"：在全部证据页到达之后、某个随机时刻提问。
- **长度上限**：正文最多 24K token。被截掉证据的问题丢掉。
- **预算**：绝对槽数，按"正文 + 结构开销"的 15–80% 随机抽取，下限是 2 页加上结构开销。约 18% 的页流不设预算压力。
- **页长上限**：`page_cap` 取这串页流里最长的那一页，环境在仪表盘上声明它。

## 不需要模型的检查（`data/qa_checks.py`）

**每个问题算四项：**
- `answer_elsewhere`：答案字符串是否也出现在非证据页上；
- `answer_in_evidence`：答案字符串是否出现在证据页上；
- `recall_needed`：只靠预算能保住的最近窗口，是否装不下全部证据，也就是不换回就答不了；
- `bm25_rank`：只用页面原文和问题做 BM25，证据页的排名。这是页标签检索能做到的上限。

**整体报告：** 页长、预算、压力出现的位置、每串页流的问题数、证据的位置和"年龄"（距提问隔了几页）的分布。

## 需要模型的必要性检查（`eval/qa_necessity.py`，在服务器 GPU 上跑）

用 Qwen3-8B 贪心解码，对每个问题看三种视图：

| 视图 | 给模型看什么 |
|---|---|
| 闭卷 | 只有问题 |
| 不含证据 | 到这一刻为止的所有页，去掉证据页 |
| 全部 | 到这一刻为止的所有页 |

只有同时满足下面三条的问题才进 SFT：
- F1(全部) ≥ 0.5；
- F1(不含证据) < 0.3；
- F1(闭卷) < 0.3。

```bash
python -m self_paging.eval.qa_necessity --model $M --tokenizer $M --streams streams.jsonl --out necessity.jsonl
```

## 第一版结果

数据规模：600 串页流（wiki 432、Qasper 168），2483 个问题，Qwen3-8B 分词器。

| 指标 | 结果 |
|---|---|
| 正文长度（10% / 50% / 90% 分位） | 2.7K / 6.1K / 10.4K token（LongBench 测评题是 2K–12K） |
| 页长 | 63 / 203 / 441 token |
| 每串的页长上限 | 414 / 590 / 888 |
| 预算 | 2.0K / 3.5K / 7.1K；不设压力的占 15.7% |
| 压力出现在第几页 | 4 / 9 / 23 |
| 每串的问题数 | 1–8，比较均匀 |
| 证据"年龄" | 1 / 9 / 25 页 |
| 证据在页流中的相对位置 | 0.04 / 0.32 / 0.75 |
| 问题先给 / 最后给 | 48% / 52% |
| **需要换回** | **31.7%**（问题先给 10.2%，最后给 51.2%） |
| 答案也出现在非证据页 | 22.3%（多为短答案的字面巧合） |
| BM25 只看原文，证据页进前 5 | 68.5%（MuSiQue 52%，HotpotQA 78%） |

## 要和用户讨论的问题

1. **需要换回的比例只有 32%**：
   - "问题先给"时，模型知道问题，只要把证据页留住就行。这练的是"换出时别把有用的换掉"，不练换回；
   - 要提高换回的比例，可以降低预算、把提问推后，或者把页流做长（每串更多道题）。
2. **答案出现在非证据页的有 22%**：大多是"Elizabeth""1999"这种短答案的字面巧合，不一定真能用那页回答。计划不在这里硬丢，交给 GPU 上的必要性检查判断：如果"不含证据"视图下模型答得出来，自然会被丢掉。
3. **多跳问题的第二跳和问题本身没有共同的词**，BM25 前 5 名只有 52–78%。
   - "换回哪页"必须一步一步来：先换回第一跳，读到桥接实体，再据此换回第二跳；
   - 所以可实现性检查也要一步一步做。这会带来多步换回的行为，正好也是多样性的来源；
   - 决策程序要按这个来设计。
4. **一页里可能混着不同主题的段落**（例如"伊朗"和一位导演），标签要能概括这种混合页。要不要改成一页只放一个主题？
5. **页流长度中位数只有 6K**，离 24K 的上限还远。要不要每串放更多道题，覆盖更长的页流？

## 下一步（等讨论之后再做）

1. 决策程序：只用可观察信息；问题出现前无从区分的页号选择，不算损失；
2. Qwen3-8B 写标签和理由，以及标签可实现性检查（按多跳分步检索）；
3. 模式探针、统计检查、最小对照对；
4. 拼成轨迹，交给服务器跑必要性检查，再 SFT。
