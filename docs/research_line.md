## 1. 一句话

**像 CLM 把上下文管理交给模型那样，把 KV 缓存的调度管理直接交给模型。**

- CLM：`C_{t+1} = f(C_t, y_t)`。模型自己选的变换 f 作用在**文本**上；改完要重新 prefill，被删的内容真的忘了。
- 本文：f 作用在 **KV 的驻留集**上。

> KV 是一份**只追加的日志** L，每个 token 的 KV 只在写入时算一次。模型能改的只有驻留集 R_t ⊆ L，|R_t| ≤ B（显存预算）。不在 R_t 里的页放在内存里（可逆），或者被删掉（不可逆）。模型的全部管理动作，就是用几个标签去改 R_t。

## 2. 为什么在 KV 层做：形式化自带的四个性质

| 性质 | 含义 | 和 CLM 比 |
|---|---|---|
| **P1 零重算** | 任何动作都不触发 prefill | CLM 每次编辑后，编辑点之后的内容都要重新 prefill；SCR 只能近似补救（[clm_notes.md](clm_notes.md) §6） |
| **P2 精确可逆** | 换回来的 KV 和原来逐位相同 | CLM 删掉就没了 |
| **P3 单次前向训练** | 整条轨迹仍是一条序列，第 t 行只看 R_t。用一个块掩码就能精确做 teacher forcing | CLM 的编辑打破了只追加，RL 只能把轨迹切段、各段重新编码（[clm_notes.md](clm_notes.md) §5） |
| **P4 删除不等于遗忘** | 页 p 换出后，p 驻留期间写下的 token 的 KV 里仍带着 p 的信息 | CLM 重新 prefill 后是真忘。这一点有利有弊，本身是研究问题（K3） |

P1–P3 是工程优势，P4 是科学问题。

## 3. 空位在哪（详见 [related_work.md](related_work.md) §0）

按三个维度给已有工作分格：谁决定（系统 / 模型）、作用对象（文本 / KV）、是否可逆。

| | 系统决定 | 模型决定 |
|---|---|---|
| **文本 · 不可逆** | 固定截断、定时摘要 | **CLM** |
| **文本 · 可逆** | 在历史上做 RAG | MemGPT / Letta 式的存档和召回；**ACM**（2607.23809）：摘要后原文存盘、可查回，Qwen3.5-9B，BrowseComp-Plus 680/150 划分，公开了 checkpoint |
| **KV · 不可逆** | StreamingLLM、H2O、SnapKV、AgentKV、Online KV Compaction（2608.00902） | **SideQuest**（2602.22603）：模型自己删工具输出的 KV，215 条样本 SFT |
| **KV · 可逆** | InfLLM、Quest、ArkVale：按问题相似度换页 | **本文** |

另有两个参照点：Declarative Attention（模型用标签声明注意力范围，但零样本、没有容量上限、不换出）；Leyline（服务端的 KV 编辑原语，策略是人写的）。

**我们占的位置**：
1. 模型自己决定的、**可逆的** KV 换页（换出 + 换回）；
2. 用结果奖励加成本做 RL（沿用 CLM 的双通道 advantage），而不是只做少量 SFT；
3. 在同一任务、同一预算下，把上表四格里"模型决定"的一列放在一起做受控对比；
4. 量化残留（P4）在什么情况下要紧。

**最大的撞车风险是 SideQuest**。动笔前必须读全文，确认它有没有换回、有没有 RL（[research_log.md](research_log.md) §7.1）。

## 4. 研究问题与假设

| 编号 | 假设 | 怎么测 | 预期 |
|---|---|---|---|
| **K1 成本** | 准确率相同时，KV 操作的总成本低于 CLM 的文本编辑，编辑越频繁差距越大 | T2 上同一模型、同一预算，比较 CLM、CLM+SCR 和本文的成本-准确率曲线 | 基本可以肯定成立，是工程结论 |
| **K2 可逆性改变策略** | 有内存层时，学出来的策略会更早换出、驻留集更小，准确率不变 | 同一套训练，分"可换回"和"只能删"两个版本，比较驻留集大小、换回次数（衡量反悔）、准确率 | 2608.00902 发现立刻压缩会掉点、等问题出现再压缩能找回大半；可逆性应该能去掉"不敢早删"的代价 |
| **K3 残留** | 新旧矛盾任务上，旧值换出后，模型仍比 CLM 重新 prefill 更容易答出旧值；旧值驻留期间写下的 token 越多越明显 | E2：可见文本完全相同的两个条件（换出 vs 删除后重新 prefill），差异只在中间页的 KV 是否带着旧值算出 | **新**。不成立也是干净的结论：说明 KV 操作可以放心替代文本删除 |
| **K4 写笔记 vs 换页** | 两种付代价方式都在动作空间里：先写笔记再换出（写入时付）、换出后需要时再换回（读取时付）。学到的比例随"以后要用什么"的可预测性变化 | T1 上调需求可预测性旋钮，统计 RL 策略的笔记 token 数和换回次数 | 可预测性高时偏笔记，低时偏换页 |
| **K5 规模** | 零样本协议遵守能力随规模上升，训练能把小模型拉上来 | E1：4B、8B（有条件加 14B/32B），训练前后对比 | DA 报告小模型协议遵守差（Gemma-4-E4B 选区成功率 58%）[S] |

## 5. 方法概要（细节见 [algorithm_design.md](algorithm_design.md)）

- **页**：每个工具观察一页，每个 assistant 回合一页。system prompt、任务描述、当前回合钉住，不能换出。
- **目录**：每页一个常驻页头，约 10–20 token（页号、工具名和参数、第一行）。**目录算进预算 B**。500 个回合约 7.5K token；更长时再做分层目录。
- **动作**：用原生 tool call（[experiment_plan.md](experiment_plan.md) §2）：
  - `kv_out`：换出到内存，可逆；
  - `kv_in`：换回；
  - `note`：写一条笔记，作为新的一页常驻。它是在源页还驻留时写的，所以 KV 里编码了源页；
  - `kv_drop`：删除，不可逆，只在"没有内存层"的对照条件里开放。
  - 所有驻留集的改变都发生在回合之间。
- **仪表盘**：每轮附一行显存水位；在 50%、75%、90% 时提醒；超预算时系统按 LRU 强制换出并记罚分（沿用 CLM 的预算机制，[clm_notes.md](clm_notes.md) §2.1）。
- **训练**：零样本 → SFT（T1 上用程序 oracle 生成轨迹，T2 上用拒绝采样）→ RL（GRPO + 双通道 advantage，效率项只落在控制标签 token 上）。

## 7. 基线

1. **Full-KV**：不设预算；
2. **系统 · 不可逆**：StreamingLLM（sink + 最近窗口）、SnapKV / H2O 式按注意力淘汰；
3. **系统 · 可逆**：Quest / InfLLM 式，每页一个代表 key，提问时取 top-k 页（在我们自己的页存储里实现，保证公平）；
4. **模型 · 文本**：CLM、CLM + SCR；MemGPT 式存档和召回；ACM（公开的 Qwen3.5-9B checkpoint）；
5. **模型 · KV · 不可逆**：本文去掉 `<in>`，相当于 SideQuest 的设定；
6. **零样本**：只靠 prompt 的本文协议，以及 DA 式的只遮蔽、不换出；
7. **Oracle**：按真值决定驻留集，给出上界。

## 8. 代价口径

上一版 proposal 的教训：搬运很便宜，一块约 150 MB 走 PCIe 4.0 x16 约 6–7 ms；而 8B 模型在 A6000 上解码一个 token 约 20–30 ms（估算，见 [research_log.md](research_log.md) §3.8）。所以**不能按搬运次数计价**。报告以下各项：

| 项 | 定义 |
|---|---|
| C_read | Σ_t \|R_t\|，即每个解码步读取的驻留 KV token 数之和。批量服务、上下文又长时，它是解码代价的主要来源；batch = 1 时权重读取占大头，多生成的控制 token 反而更贵（折算方法见 [algorithm_design.md](algorithm_design.md) §5） |
| C_prefill | 新 token 的 prefill FLOPs，加上所有重新 prefill（CLM 的口径，复用 `clm/clm_harness/flops_metrics`）。本文的重新 prefill 恒为 0 |
| C_ctrl | 控制标签和笔记的 token 数 |
| C_pcie | 换入换出的字节数 |
| 峰值驻留 | max_t \|R_t\|，硬约束 ≤ B |

主图是准确率对 (C_read + C_prefill 折算) 的 Pareto 曲线。HF 原型只给解析成本；墙钟延迟要等接入 vLLM 或 SGLang 的 block table 之后才能报告，写作时要说清楚。

## 9. 分阶段计划

| 阶段 | 内容 | 时长 | 检查点 |
|---|---|---|---|
| 0 | 原型：页存储、协议状态机、拼 cache 推理、块掩码训练；P1–P3 等价性测试。在云端用随机初始化的小 Qwen3 配置，只需 CPU | 约 1 周 | 等价性测试全部通过 |
| 1 | **E0–E2**（只推理，Qwen3-8B，用户 GPU） | 1–2 周 | **继续/止损**：E0 看有没有准确率提升空间；E1 看零样本遵守率；E2 看残留 |
| 2 | SFT：T1 程序 oracle 轨迹 + T2 拒绝采样 | 约 2 周 | 协议遵守率 > 95%，T1 准确率不低于零样本 |
| 3 | RL + T2 全量对比；K1、K2、K4 | 3–4 周 | 主表和 Pareto 图 |
| 4 | 扩展（T3 视频，或接入服务框架测延迟）+ 写作 | 2–3 周 | — |

**E0 是最关键的检查点**：如果 Quest 式的系统换页在 T1/T2 上已经接近 oracle，"让模型决定"在准确率上就没有空间，论文要改成以成本（K1）、受控对比和残留（K3）为主。

## 10. 风险与兜底

| 风险 | 兜底 |
|---|---|
| SideQuest 已经做了换回或 RL | 贡献收缩到受控对比（§3 表格）、残留 K3、写笔记 vs 换页 K4 |
| E0 负结果：系统换页接近 oracle | 同上，改讲成本和机制 |
| 小模型学不会协议 | 加重 SFT；或者换成更大的模型，只用 LoRA |
| 延迟收益只有解析值 | 原型阶段只报 C_read 等解析成本；墙钟留到接入服务框架之后 |
| 全局位置号随日志增长，会超出 Qwen3-8B 原生的 32K | T1 把日志控制在 32K 内；BCP、LongMemEval 对所有方法统一开 YaRN；E0b 测位置空洞本身的影响（[experiment_plan.md](experiment_plan.md) §1.2） |
| Qwen3-8B 在 BrowseComp-Plus 上准确率可能太低，RL 学不动 | E1 先测；备选是换稠密检索器，或者用多跳问答做 RL（[experiment_plan.md](experiment_plan.md) §3.3） |
| 混合线性注意力模型越来越多，结论的适用范围会受质疑 | 作为局限讨论；主实验坚持用 dense 模型，保证机制干净 |
| 相邻工作出得很快（2026 年 6–10 月已有十几篇 agent KV 管理论文） | 尽快完成阶段 1；每次动笔前一周重新检索（[related_work.md](related_work.md) §10） |

## 11. 资源需求

- **模型**：**Qwen3-8B**（纯 dense，2026-11-15 定）。用户服务器上已有的 Qwen3.5-9B 用作本地评判模型和备用老师。操作 KV 只能用开源模型，所以**这条线不需要模型 API 密钥**。
- **GPU**：E0–E2 单卡即可；RL 需要多卡。原 proposal 提到 4×RTX A6000，**待用户确认实际硬件**。
- **云端限制**：当前云环境没有 GPU，huggingface.co 被拦截，拉不到权重（[research_log.md](research_log.md) §6.1）。云端只做代码、CPU 上的小模型测试和文档；实验在用户机器上跑。
- **评判模型**：T2 用本地开源模型做评判，不依赖外部 API。

## 12. 论文结构草案

1. 引言：CLM 证明了"让模型自己管上下文"可行，但它作用在文本上，每次编辑都要重算、删了就回不来
2. 形式化：只追加日志 + 驻留集；P1–P4
3. 方法：页、目录、动作、仪表盘；推理和训练的精确实现
4. 训练：零样本 → SFT → RL，以及代价口径
5. 主结果：T1、T2 上和 §7 全部基线比较，Pareto 曲线（K1）
6. 可逆性如何改变策略（K2）
7. 残留：删除不等于遗忘（K3）
8. 写笔记 vs 换页（K4），规模（K5）
9. 扩展：视频（T3）或服务框架延迟
10. 局限：混合架构、解析成本 vs 墙钟
