# SFT v2 诊断：为什么还不会 kv_out / kv_in，基线为什么慢（2026-11-17）

数据来源都是服务器 agent 的归档 `experiments/self_paging_v2_20261117/`（提交 `e4cd082`），包括：
- T1 修正基线评测里的 55 局 `model`（种子 100000–100010，5 档预算）；
- LongBench 19 题 `model`；
- SFT v2 数据统计 `training/data/data-accepted.json`。

T1 部分可以用 `python -m self_paging.eval.t1_audit` 复现。**RL 之前先读本文**，§4 的修改做完之前，不建议开始 RL。

---

## 1. kv_out：T1 上会做，但不看预算；LongBench 上基本不做

**现象**

| | 主动 kv_out | 系统兜底换出 | 其他 |
|---|---|---|---|
| T1（55 局） | 每局 16–19 次 | 每局 0–0.27 次 | 无 |
| LongBench（19 题） | 成功 18 次 | 121 次 | 截断 18,315 token |

- **T1 上的换出不随预算变化**：驻留环境页的比例几乎不随预算变（预算 0.25 时 26%，0.6 时 31%）。发出 kv_out 时的驻留占比，中位数在 0.6 预算下只有 45%。
  - 轨迹例子（种子 100001，预算 0.6，B = 8299）：驻留 1248 时就换出第 5、13 页，理由是套话："no longer needed for the current shelf state""page out shelves above S1"，而第 13 页的内容是 dispatch S2；
  - 等驻留涨到 3000 多、真有压力了，反而不再换出。
- **LongBench 上模型每回合只调 `next_session`**：每页 1024 token、预算 4096 槽，第 4 页就装不下，全靠系统兜底换出和截断。

**原因**
1. **换出时机取决于模型看不到的信息**。oracle 按下一页的真实大小（`T1Oracle._size(st, env.cursor)`）决定腾多少空间，仪表盘只显示"已驻留 / 预算"。模型无从知道下一页多大，只能学一个平均习惯。
2. **SFT 数据的主体不是压力驱动的换出**。2400 条数据里：
   - eager 750 条、notes 720 条，这两种都是读完就换出；
   - paging（按压力换出）只有 285 条；
   - 合计 26,614 次 kv_out。

   模型学到的是"早换出、每页读完就换出"这个习惯。
3. **理由文本是模板**，和页面内容对不上，模型没法从理由里学到判断规则。
4. **分布太窄**：SFT 只有 T1，每页 100–900 token，预算按比例给。LongBench 每页 1024 token、预算是绝对的 4096 槽，"下一页一来就超预算"这种情况在训练里没出现过。

## 2. kv_in：不会，在 T1 上也没必要会

**现象**
- T1 上每局约 1 次 `kv_in`，常常是换回最早换出的那一页，像一个仪式；
- 220 个决策里，有 169 个作答时驻留的环境文本按规则读者不够用，但其中 159 个照样答对；
- LongBench 上 `kv_in` 为 0。

**原因**
1. **T1 默认配置可以走捷径**。用 `t1_audit shortcut` 测：只看最近 5 页，并假设没见过的货架都已占用（货架是从低号往上填的），种子 100000–100299 上：

   | 决策类型 | 准确率 |
   |---|---|
   | explicit | 0.93 |
   | implicit | 0.90 |
   | delayed | 0.82 |

   同一批世界上，StreamingLLM 和 H2O 在 0.25–0.6 各档预算下都是 **1.0**。所以在 T1 上，换不换回不影响对错。SFT 数据里的 `kv_in` 是 oracle 按严格规则读者的最小充分集定的，在模型看来没有来由。RL 同样不会奖励它：反事实信用只在"信息不在才答错"时触发，而模型靠捷径答对了。
2. **"需要"的定义和模型的实际需要不一致**。严格规则读者把没见过的货架当成空的，LLM 不会这么做。所以 `minimal_sufficient` 高估了模型的需要。
3. **通用文档没有页面内容的线索**。LongBench 的页头只有 `[[PAGE 5 tool=next_session]]`。问题最后才出现时，模型不知道答案在哪页，只能瞎猜（例子：第 24 题直接把 "Paragraph 82" 当成答案交了）。T1 的页头摘要是环境替模型写的，真实文档里没有这样的东西。

**结论**：同意"这是训练上的问题"。更准确地说是**数据和环境**的问题：
- 动作的触发条件模型看不到；
- 换回在 T1 上没有必要；
- 换回需要的线索在通用文档上不存在。

都不是模型能力的问题。

## 3. H2O / StreamingLLM 测得慢：是我们的移植实现造成的

**数字**（LongBench，每题平均）：

| | Full | 模型自主换页 | H2O | StreamingLLM |
|---|---|---|---|---|
| 文档读取 | 3.6 s | 2.8 s | 159 s | 145 s |
| 生成（每 token） | 61 ms | — | 68 ms | 61 ms |

- **生成速度基本一样**，差距全在文档读取。
- H2O 每题淘汰约 2414 个 token，159 s / 2414 ≈ 66 ms，正好是解码一个 token 的时间。

**原因**：`hf/faithful_cache.py` 要求峰值 ≤ B，还预留了 1 个槽。缓存满了以后，`n = min(…, budget − previous)` 等于 1，**文档预填充退化成一个 token 一次整模型前向**，读文档变成了逐 token 解码。

**作者代码不是这样做的**（[K]，凭记忆，请对照 `docs/faithful_baselines.md` 里固定的提交核实）：
- StreamingLLM 的运行脚本在每段 prompt 之前先调用 `kv_cache.evict_for_space(past_key_values, space_needed)`，再一次前向整段；
- H2O 先一次前向整段 prompt，再淘汰到 cache 大小（峰值会暂时超过预算）。

**算法本身的开销**：
- StreamingLLM 只看窗口，开销比 Full 还小；
- H2O 要多算一次注意力概率，作者实现用 eager 注意力顺带就拿到了，不是几十倍的差距。

**修复**：`FaithfulKV(..., prefill='space')`，命令行加 `--prefill-evict space`（`longbench_v1`、`faithful_eval` 都支持），默认值仍是原来的逐 token 方式。
- **做法**：每块（最多 128 个 token）进来之前，按方法自己的保留规则先淘汰到 `B − 块长`，再一次前向整块。峰值仍然 ≤ B，解码阶段不变；
- **小模型实测**：6000 token 的文档、B = 4096，前向次数从 1936 降到 47。峰值相同，淘汰的 token 数相同，StreamingLLM 最终保留的位置和逐 token 方式完全一致；
- **代价**：块内的 token 最多少看 128 个旧槽；
- **预计**：8B 上文档读取会回到 Full 的量级。

**注意**：
- 已完成的 LongBench 结果是逐 token 方式跑的。新方式要另开 `--out` 重跑，两种结果不能混在一起；
- LongBench 上模型自主换页的输入被截断了 18,315 token，它读得快有一部分是因为少读了。

## 4. 建议的修法（RL 之前）

**A. 让换出时机可观察**（kv_out 的可实现性，对应 §2.1 对 kv_in 的修法）
- 环境约定页大小上限 P，仪表盘显示：
  ```
  [KV] resident 3769/4096 | free 327 | next page ≤ 1024
  ```
- oracle 只按可观察的量决定：当 free < P + 回合开销时才换出，换出量为 P + 开销 − free。不再用下一页的真实大小；
- 按压力换出要成为数据的主体，eager 和 notes 合计 ≤ 20%；
- 理由文本要引用仪表盘和页头摘要，例如：
  ```
  free 310 < next ≤ 1024; paging out 13 (dispatch S2 already applied)
  ```
- 新增门控：没有压力也换出（free ≥ P + 开销），且不是带标签的 eager 样本的轨迹，丢掉。

**B. 让换回成为必要**
- T1 加一个"捷径门"：只保留满足下面两条的决策（训练、题库、评测都用）。在 `data/build_t1_sft.py` 和 `data/rl_preparation.py` 里实现：
  - `recency_reader` 在预算保得住的那段最近窗口内答错；
  - 按 token 预算算出的 StreamingLLM 窗口内，规则读者也答错。
- 去掉"从低往上填"的先验：入库放到随机的空货架上（答案仍是最低的空货架），这样没见过的货架就不能默认已占用；
- 验收：`t1_audit shortcut` 最近 5 页的命中率 ≤ 0.3；评测上 StreamingLLM 不应接近 1.0。

**C. 通用文档要有页标签**
- `kv_out` 加一个 `label` 参数：模型写一句话描述这一页，它作为该页的常驻页头。这是唯一通用的办法，环境不会替模型写摘要。做法和 CLM 的摘要一样，只是写在 KV 页头上；
- 数据来源：
  - 文档 QA 的 oracle 按证据位置决定什么时候 `kv_in`；
  - 标签由老师模型写（Qwen3.5-9B，或用特权提示）；
  - LongBench 是测试集，不能用来训练。训练用 BCP（D3）或合成的多文档检索。

**D. 扩大分布**
- T1 的页大小和预算要更多样，包括 1024 token 的页和绝对 4096 槽的预算；
- 混入文档类任务。

**E. RL 放在 A–C 之后**
- 现在的 T1 上换回不影响奖励，奖励信号里没有"该换回"这件事；
- 修好环境之后，现有的 reward v2（卫生惩罚里含强制换出、反事实信用）才有东西可学。

---

另外，修正基线后的 T1 结果（StreamingLLM、H2O 各档全是 1.0）说明：**T1 默认配置不能当主表**。主表要等 B 里的硬配置做完、过了捷径门之后再跑。
