# RL 设计：数据和奖励（基于 2026-11-16 的 SFT 结果）

本文是在读了 `experiments/self_paging_20261116/`（SFT 431 步、50 个世界 × 4 种配置的评测、RL CPU 准备、`provenance/RL-DATA-PROPOSAL.md`）之后写的。它补充并在冲突处取代 [data_and_training.md](data_and_training.md) §3。执行实验的 agent 在开始 RL 之前，必须先读 §2 和 §7。

---

## 0. 结论

1. **SFT 模型的错误几乎都是"信息不在"，而不是"推理错"**：四种配置共 120 个错误决策，115 个属于这一类，4 个是推理错，1 个是没走到决策点。错误集中在 **delayed（延迟生效的隔离通知）** 这类题上（90/120 = 75%）。模型会把隔离通知换出去，但几乎从不换回来：200 个决策里 `kv_in` 只有 20–25 次。
2. **根因在协议和 SFT 数据，不在模型能力**：oracle 换出隔离通知，靠未来信息决定换回；但 T1 的页头只写 `[[PAGE n tool=next_events]]`，模型从可见内容里**无法知道该换回哪一页**。这种"换回"是学不会的。
3. **所以 RL 之前先修可实现性**（§2）：页头加内容摘要；SFT 数据过滤掉无法推断的换回；修好 `kv_tools=False` 时仍然执行 KV 调用的 bug。不修这些就上 RL，`kv_in` 的探索基本等于随机猜页号。
4. **奖励 = 任务分 + 轻量卫生惩罚 + 成功门控的效率项 + 反事实信用**（§4）。反事实信用是新增的主要建议：用环境真值找出"导致答错的那次换出"，把负的优势直接加在那次 `kv_out` 调用的 token 上，解决换出和决策之间隔着 5–25 个回合的信用分配问题。
5. **题库沿用 agent 的划分和 CPU 准备**（§3），补充三点：按决策类型分层，并提高 delayed 题的比重；画像要看部分得分方差和效率信号，不只看全对率；OOD 要重新生成在 32K 以内的版本。

## 1. SFT 结果说明了什么

工具：`python -m self_paging.eval.error_analysis --records 'experiments/self_paging_20261116/raw/*.jsonl.gz'`。

判断方法：对每个答错的决策，看从决策页到达、到取下一页之间的每个回合，可见的环境页文本能不能让规则读者答对。模型写的笔记和它之前回合里的推导**没有算进去**（解码需要分词器），所以"信息不在"是上界；但按决策类型的分布不受影响。

| 配置 | 答错 | 信息不在 | 信息在、推理错 | 答错里 delayed 题 | 缺的页：隔离通知 / 更正或盘点 / 入库出库记录 |
|---|---|---|---|---|---|
| 名义 full@1.0（KV 工具实际没关） | 18 | 16 | 2 | 16 | 15 / 3 / 32 |
| model@0.6 | 31 | 30 | 1 | 22 | 19 / 5 / 41 |
| model@0.4 | 29 | 28 | 1 | 22 | 14 / 6 / 45 |
| model@0.25 | 42 | 41 | 0 | 30 | 27 / 8 / 80 |

另外三个观察：
- **没有预算压力也在换出**：名义 full 换出了 461 页，结果 delayed 题错了 16 个。这说明 SFT 教出了一个"不管有没有压力都换出"的习惯；
- **换回极少**：每种配置 200 个决策里只有 20–25 次 `kv_in`；
- **低预算下大量系统兜底**：0.25 预算时强制换出 194 次、截断 7958 个 token、非法调用 39 次。信息就是在这些地方丢掉的。

**根因核实**：用 oracle 造的 SFT 数据（字符级分词器，20 个种子，预算 0.6/0.45）里，带隔离通知的页被换出 115 次，换回只有约 50 次。Belady 本来就会先换出"下次使用最远"的页，而隔离通知正是那种要等很久才会用到的页。换回的时机由 oracle 的未来信息决定，页头又不提供任何线索，所以对模型来说是不可实现的。agent 用的 SFT 数据基于 `797680f`，那时还没有主动换出模式，但只换页的 Belady 模式也有同样的问题。

## 2. RL 之前必须先修的三件事

> **实现状态（2026-11-16，提交在 `claude/bold-lamport-xki29h`）**：§2.1、§2.2、§2.3、§4（reward v2）、§7.1 都已实现并有测试（`tests/test_rl_v2.py`）。执行顺序见 runbook 的"当前要做的：SFT v2 → RL v2"。用新规则造的数据（字符级分词器，40 个种子）：403 条，所有保留的换回都能从页头推断；paging、eager、mixed 模式里含换回的 episode 占 68–100%。

### 2.1 页头加内容摘要（让"换回"变得可实现）

T1 的页头改成由系统生成一行摘要，只列关键事件、不列遥测：

```
[[PAGE 12 tool=next_events | steps 812-830 | QUARANTINE S5; CORRECTION S3; 4 stores; 2 dispatches]]
```

- 这和 BCP 的页头（`tool=search q="..."`）、用户原 proposal 里的"缩略图目录"是同一个思路：给模型一个能决定换回哪页的目录；
- 摘要计入预算，每页约 15–30 token；
- **消融**：去掉摘要，用来说明"目录"对模型管 KV 的作用；
- 实现位置：`envs/t1_warehouse.py` 给每页生成摘要，`agent/episode.py` 把它写进页头。所有 T1 环境都要统一用新页头，SFT 数据也要重造。

### 2.2 SFT 数据的可实现性过滤，补上"换回"这一条

`data_and_training.md` §2.6 的过滤只管了换出，没管换回。补充：
- 一次 `kv_in` 只有在**可见内容里有线索指向被换回的页**时才保留：页头摘要里提到了相关货架，或者某条笔记提到了它；
- 换出带有**长期约束**的页（隔离通知）时，如果之后的换回无法由线索推断，就改成"先写一条笔记再换出"（笔记写明 `S5 quarantined`），或者干脆不换出；
- 有了 §2.1 之后，大部分换回都会自然变得可推断。

然后用新数据做一次短 SFT：从 431 步的权重继续训练，或者重新训一遍。之后用 `error_analysis` 复查，"信息不在"的占比应该明显下降，delayed 题的 `kv_in` 应该明显上升。

### 2.3 修好执行器的工具权限

`kv_tools=False` 时，KV 调用必须被拒绝，并按"未知工具"计为非法调用。否则 Full、Recent、QuestPage 都不是纯系统基线（agent 的 README 已经指出）。

## 3. RL 数据（题库）

agent 的方案（`provenance/RL-DATA-PROPOSAL.md`、`self_paging/data/rl_preparation.py`）总体合理，保留：
- **划分**：训练 10000–13000、开发 92000–92200、测试 110000–110200、OOD 210000–210100；排除所有历史种子；按世界内容哈希检查跨划分重叠；
- **预算配额**：无预算 10%、0.6 / 0.4 / 0.25 各 30%；
- **决策点数**：2–6 均衡；
- **先小规模画像**：64 × 4 → 240 × 4；
- **组的定义**：同一个 (种子, 配置, 预算) 一组，G = 8；不同预算不放进同一组。

补充和修改：

| 项 | 建议 | 理由 |
|---|---|---|
| **按决策类型分层** | 题库按 delayed 决策的数量和关键事件到决策的距离分层，delayed 决策至少占 40%；远距离（gap > 15）的题单独成桶 | SFT 的错误 75% 集中在 delayed 题。均匀抽题时，大部分梯度花在已经会的题上 |
| **无预算题保留 10%，单独监控** | 记录这些题上的换出次数和准确率 | 名义 full 证明模型在没有压力时也会乱换出。效率项会**鼓励**这种换出（换出就能少读 KV），只靠成功门控来防止。要盯住它有没有伤到准确率 |
| **画像指标** | 每道题记录：平均任务分、组内方差、全对率、每类决策的正确率、换回次数、卫生计数 | agent 已经指出 0/4 和 4/4 不可靠，部分得分（0.25、0.5、0.75）也有信号 |
| **保留"任务分相同、效率不同"的组** | 只要组内任何 token 的优势不为 0 就保留（agent 的第 1 点） | 否则全对的组被丢掉，效率项永远学不到 |
| **课程** | 先用 0.6 和 0.4（SFT 准确率约 85%），20–50 步后再加入 0.25 | 0.25 下强制换出和截断太多，奖励噪声大 |
| **OOD 重新生成** | 当前 OOD 300 个条件里只有 1 个能放进 32K。改成 7–9 个决策点、但每页更短（每页 3–6 个事件）、warmup 更短，保证 32K 以内；128K + YaRN 的版本留到以后 | 否则没有可用的外推评测 |
| **抽题器** | 部署的 `grpo.py` 没有我分支上的 `PromptSampler`（`223cc65`）。建议按它的思路接：按权重抽题；按（预算, 决策点数, delayed 数）分桶，追踪的指标改成"组内奖励方差"，而不是全对率；方差接近 0 的桶降权，但保留至少 10% 的探索权重 | agent 的第 2 点 |

## 4. 奖励和优势

记 n 为这一局的决策数。

### 4.1 任务分（主信号）

```
R_task = 答对的决策数 / n          # 没作答、episode 提前结束 → 剩下的决策都算错
```

保持不变。不奖励换页次数，不奖励理由写得好坏。

### 4.2 卫生惩罚（小、有上限）

| 事件 | 每次惩罚 | 上限 |
|---|---|---|
| 系统强制换出（模型没腾出空间） | −0.02 | −0.10 |
| 某页工具输出被截断 | −0.03 | −0.10 |
| 非法工具调用 | −0.05 | −0.10 |
| KV 错误（换回超预算、页号不存在等） | −0.02 | −0.05 |

- 卫生惩罚的总和不超过 −0.25，约等于 4 个决策时答错 1 题的分量。它只起"加速"作用，不能压过任务分；
- 理由：在 0.25 预算下，信息恰恰是通过强制换出和截断丢掉的。只靠"最后答错"来惩罚，信号太稀；
- 这些计数必须来自执行器的回执（agent 已经指出不能只读 `meta.invalid`）。

### 4.3 效率项（成功门控，CLM 双通道）

```
a_eff_i = clip((C̄_succ − C_i) / C̄_succ, −1, 1)    # 只在组内"任务全对且无卫生惩罚"的轨迹之间比较
```

- 只加在 KV 工具调用的 token 上；
- **前 50 步 w_eff = 0**，等任务分稳定后，再线性升到 0.1–0.25。SFT 模型本来就过度换出，太早加效率项会加剧这个问题；
- 无预算的题也计算效率项（换出确实省了 KV 读取），但要按 §3 监控准确率。

### 4.4 反事实信用（新增，主要建议）

问题在于：错误的换出发生在决策之前 5–25 个回合（换出隔离通知 → 很多页之后才用到），整局一个标量奖励很难把功过归到那次换出上。环境有真值，可以精确找出"如果那一页还在，就能答对"：

```
对每个决策 d（gold g；V_d = 作答那一回合可见的环境页文本）:
  如果答错，并且 rule_read(V_d) != g:                                  # 信息确实不在
      对每个缺失的页 p，如果 rule_read(V_d ∪ {p}) == g，                # p 是"有它就能答对"的页
         并且 p 最后一次是被模型自己的 kv_out 换出的（不是系统强制换出）:
            给那次 kv_out 调用的 token 加优势 −c                        # 有害换出
  如果答对，并且 d 之前有一次 kv_in 换回了页 q，并且 rule_read(V_d − {q}) != g:
      给那次 kv_in 调用的 token 加优势 +c                               # 有用的换回
  如果答错但 rule_read(V_d) == g:   不做 KV 信用（推理错，交给任务分）

c = 0.5 / n
A[i, t] = A_task(组内) + w_eff · a_eff_i · ctrl_mask[t] + w_credit · credit_i[t]      # w_credit = 1
```

- **为什么合理**：真值只用来算奖励，不进入模型上下文，和"用标准答案判对错"是同一性质；它是可验证的，不是模型打分；
- **为什么只在答错时追责**：规则读者看不懂模型自己写的笔记。答对时，那条笔记可能起了作用，所以不追责；
- **风险**：可能鼓励"什么都不换出"。预算和截断惩罚会抵消这种倾向；无预算的题上，效率项会抵消；
- **消融**：w_credit = 0（纯结果奖励）对比 w_credit = 1。这本身就是论文里一个有意义的结果：KV 管理的信用分配；
- **实现**：rollout 时就记录每个 KV 调用作用在哪些页、在哪个回合；episode 结束后按上面的规则算出 `credit_i[t]`，作为第三个通道加进 `train/advantage.py`。T2（BCP）上没有规则读者，可以用 evidence/gold 文档代替。

### 4.5 不要做的

- 不按换页次数、笔记长度、理由文采给奖励；
- 不用模型当评委来评 KV 动作；
- 不用测试题选 checkpoint（agent 已经遵守）。

## 5. 训练细节

- **优势和损失**：沿用 GRPO + token 级裁剪 + TIS；
- **组的保留规则**：只要有 token 的优势不为 0 就保留（§3）；
- **G**：先 G = 4 跑 5–10 步，测吞吐和 bf16 下 rollout 与训练 log-prob 的差异，再用 G = 8；
- **每 20 步在开发集上评测**，用 `error_analysis` 看"信息不在"的占比、delayed 题的准确率和 `kv_in` 次数。
- **每步都要记录的诊断**：
  - 每类决策（explicit / implicit / delayed）的正确率；
  - 作答时信息可用的比例（规则读者判断，精确）；
  - delayed 决策前的换回次数；
  - 无预算题上的换出次数；
  - 卫生计数；
  - 反事实信用的正负次数。

## 6. 评测

同一套 checkpoint，在开发集、测试集、OOD 上都报告以下几项：
- 任务准确率；
- 按决策类型拆开的准确率；
- 作答时信息可用的比例；
- 换出 / 换回 / 笔记次数；
- 卫生计数；
- 代价 C；
- 严格 Full（执行器修好之后）、Recent、QuestPage、修复版 Belady 的对比。

按世界配对，以世界为单位聚类算置信区间（一个世界里的 4 个决策不独立，agent 已经指出）。

## 8. 建议的顺序

1. 修执行器的工具权限（§2.3）；页头加摘要（§2.1）；SFT 数据补上换回的可实现性过滤（§2.2）；修 `BeladyPager` 的空间估算（§7.1）；
2. 用新数据短 SFT，跑 `error_analysis`，确认"信息不在"的占比下降、delayed 题的 `kv_in` 上升；
3. 实现奖励的四个部分（§4）和诊断（§5），写单元测试，特别是反事实信用（构造一个"换出隔离通知 → delayed 题答错"的轨迹，检查负信用正好落在那次 `kv_out` 上）；
4. 题库按 §3 补充分层，重新生成 OOD；64 × 4 试画像；
5. G = 4 冒烟 → G = 8，RL-1 只用 T1，先 0.6 和 0.4，再加 0.25；
6. 消融：w_credit = 0、w_eff = 0、没有页头摘要、只能删（K2）。
