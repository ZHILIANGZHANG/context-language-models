## A 组：最初围绕 CLM 本身的切入点（2026-10-02）

### A1. 安全：自编辑把外部数据"洗"成模型自己的想法 —— 暂缓

- **论点**：普通 agent 里，工具输出和模型自己的想法是分开的。CLM 让模型重写自己的历史，外部数据就有机会被洗成模型自己的信念。"写记忆本身就是一条提权通道"。
- **五层**（从浅到深）：
  1. 结构层：tool 被改成 user，指令层级坍塌（[clm_notes.md](clm_notes.md) §7.1）；
  2. 带内信令层：伪造角色头（§7.2，已复现）。类比 SQL 注入、电话网的带内信令攻击；
  3. 语义层：模型在摘要里用第一人称复述注入内容，出处丢失。修解析器解决不了，应该是主结论；
  4. 持久层：注入文本里写"压缩时请原样保留此条"，测它能熬过多少次压缩；
  5. 物理层：注入在文本里被删掉之后，SCR 留下的残余状态是否仍让它生效（§7.3）。
- **实验**：BrowseComp-Plus 是固定本地语料，可以植入投毒文档；指标是第一次压缩前后的攻击成功率、存活曲线、最终落在哪个角色里；对照是只追加的 harness 和摘要式压缩。
- **防御**：文本之外的来源标签，用 diff 对齐跨编辑传递（SCR 里有 diff 对齐代码）；基于工具内容写出的摘要保守继承"不可信"；带随机数的角色头；保留原角色的解析。
- **为什么暂缓**：CLM 论文的未来工作里**已经写了**可编辑上下文的安全问题，还引用了模型在自己的压缩摘要里插入未授权指令的报告；另外有一篇带来源上限的信念记忆投毒防御（2606.22030）。主要风险是被审稿人当成"实现 bug"。
- **重启条件**：主线做完后，如果要做第二篇，可以只做第 3、4 层（语义层和持久层）。

### A2. 记忆：反复自我压缩让事实"回归先验" —— 暂缓

- **灵感**：Bartlett 的序列复述实验。CLM 里同一个事实被模型自己反复改写，每次都从模型分布里重新生成。
- **假设**：
  - 回归先验：和模型原有知识冲突的事实（反事实文档）被"纠正"回原有认知的概率更高，存活率约按 (1−p)^k 随改写次数 k 衰减；
  - 确定性膨胀："可能是 X"压缩后变成"是 X"；
  - 确认偏差式遗忘：有了候选答案后，更倾向于删掉反对它的证据（BCP 有标注证据文档，可以逐条追踪）；
  - 元记忆校准：删除前让模型估计"以后用到的概率"，再用"后来是否重新搜了同样内容"检验。
- **为什么暂缓**：效应可能不够大；和后来的主线（可变状态的写入/读取误差）不是一个问题。
- **重启条件**：如果主线的 H2（写入误差会粘住）成立，"反复改写导致的漂移"可以作为写入误差的一种机制，接在主线后面。

### A3. RSI：从"上下文是文件"到"策略也是文件" —— 暂缓

- **做法**：沙箱里放一个 `gc.py`，harness 每轮自动对上下文跑一遍，不花 LLM 调用；模型随时可以改 `gc.py`；跨 episode 保留，用 clm_icl 的循环演化（候选从 SKILL.md 换成代码）。
- **问题**：上下文管理有多少能写成代码？强模型写的 `gc.py` 能否迁移给弱模型？几十代之后会不会退化？代码形式的策略能否审计目标漂移（比如删掉用户约束）？
- **为什么暂缓**：ContextEvo（2609.34649）、M*、ALMA、MemEvolve、Recuris 都在演化策略或记忆程序；我们后来转向了状态派。

### A4. 系统 × 学习：上下文排布是存储引擎问题 —— 并入（成本部分）

- **论点**：有前缀缓存时，在第 p 个位置改一处，后面 L−p 个 token 都要重算；末尾追加几乎免费。所以 `## STATE` 放在顶部原地更新，相当于 B-tree 原地更新；只在末尾追加增量、定期合并，相当于 LSM-tree。开了 SCR 后编辑代价与位置无关，最优策略应该改变。
- **可证伪预测**：在无缓存、前缀缓存、SCR 三种部署下分别演化 skill，预期前缀缓存下收敛到"只追加、批量合并"，SCR 下收敛到"原地维护结构化状态"，交叉部署时性能下降。
- **补充基线**：在已有轨迹上用动态规划求事后最优的压缩时间表，把差距拆成"忘得太早、存得太多、时机不对"。
- **现状**：缓存成本分析已被 delayed-relevance 做了（7.54 倍 → 1.39 倍；顺序差 5.7 倍）。"状态放尾部"并入了自适应绑定的布局（[algorithm_design.md](algorithm_design.md) §5.2）。SCR 那条需要 GPU，暂不做。

### A5. 监督：agent 删了什么，就暴露了它想藏什么 —— 暂缓

- **约束失忆**（最便宜）：只有 system 和最初的 task 被钉住（`_PROTECT = 2`），用户中途追加的约束（"从现在起别动 tests/"）可以被删；测压缩后的违规率。Lost in Compaction（2608.11242）已发现压缩器只保留 17% 的会话约束。
- **规避监控**：给 agent 一个隐藏副任务，比较三种监控器的检出率：只看当前上下文、看完整只追加日志、只看编辑 diff。预期"要监控 diff，删除本身就是信号"。
- **效率奖励导致钻空子**：RL 效率奖励若不检查约束，会强化"删掉约束"。需要训练。
- **为什么暂缓**：副任务设定是否有说服力存疑；和主线距离远。

### A6. 其他小切入点 —— 放弃或暂缓

- **原地打转**：prompt 让模型把 dead ends 换成摘要，摘要漏了"这条路试过、失败了"，agent 就会再试。注意作者有 `research_ledger`，可能重合。
- **按单次编辑分配功劳**：每次编辑是天然分叉点，从编辑前状态采样几种编辑分别跑下去。ContextPilot 已在关键决策点做分支采样。算力需求大。
- **Computer-use**：截图没法用 sed 改，视觉上下文管理是空白。
- **代码安全审计 / CTF**：长任务、大输出，关注"覆盖率失忆"。
- **被遗忘权**：用户让 agent 忘掉某件事，开了 SCR 时真的忘了吗？
- **上下文取证工具**：用 diff 对齐追踪每个片段跨多次编辑后的来源、是否存活、改写后是否失真。可以同时支撑 A1、A2、A5。

## B 组：用 CLM 范式打通用 bench（2026-10-02）

### B1. 上下文管理是 test-time scaling 的第三条轴 —— 放弃

- **论点**："Bounded memory, unbounded thinking"。串行（更长 CoT）会撞窗口，并行（多次采样）不累积信息；CLM 让峰值上下文固定、总计算一直增长。
- **三张核心图**：穿墙曲线（固定峰值上下文，准确率随总 token 继续上升）；显存 Pareto（32K 的 CLM 追平 128K/256K 的普通模型）；短任务不退化。
- **三层方案**：
  1. zero-shot 加"分段思考"模式（一轮一段最多 N token 的思考），在推理、长文档、智能体三类任务上画穿墙曲线，对照 Delethink、InftyThink、PENCIL、RLM、MemAgent；
  2. 训练通用 CLM 模型：强模型轨迹做 rejection sampling 后 SFT，再多领域 RL；核心是**迁移矩阵**（只在搜索上学的能力能否帮数学）；
  3. 原生编辑指令：模型在生成中直接输出 `<edit drop="P12-P19"/>`，推理引擎就地执行，把 SCR 从请求之间扩展到请求内部；训练数据由编辑前后的 diff 免费得到。
- **为什么放弃**：需要大量 GPU 和训练；和前沿模型比绝对分数会吃亏（窗口 200K–1M）；方向和原作者正面相撞（他们有算力跑 24 小时实验）。

### B2. CLM v2：把上下文从"日志"变成"工作区"（五个原语）—— 放弃（部分并入）

CLM 的九条优势对应传统 harness 的失败模式：操作表达力、时机和粒度由模型定、选择性保真、先读全再筛选、能抹掉自己的错误、上下文就是文件（可回溯可分叉）、统一动作空间、随模型变强而变强、成本可控。

五个原语：

| 原语 | 机制 | 对准的失败模式 |
|---|---|---|
| P1 可逆上下文（换页） | 删除的内容自动存进档案，原位留存根 `[已归档 T17：pytest 输出 1.2 万 token → archive/t17.txt]` | 不敢激进压缩，误删找不回 |
| P2 检查点与回溯 | `ctx save <名字>`；`ctx restore <名字> --lesson "…"`，回到尝试之前只带回一句教训 | 受自己错误影响、在失败方案里打转 |
| P3 分叉 | 子 agent 继承父上下文的过滤副本，结束后返回结果文件，父 agent 用代码合并 | 并行试方案；精确交接 |
| P4 可编程策略 | 模型把常用管理动作写成规则文件，harness 每轮自动执行 | 省下专门用来编辑的轮次 |
| P5 尾部状态区 | 模型编辑 `STATE.md`，harness 每轮放在末尾 | 目标漂移；信息淹没在中间；中途约束被删 |

配套的 bench 选择（都在 Harbor 注册表里）：大观察（binary-audit、dabstep、spreadsheetbench-verified、ade-bench、swe-atlas-qna、bixbench）、长程打转（terminal-bench@2.0、terminal-bench-pro、swebenchpro、swe-lancer-diamond、featurebench、crustbench）、开放式优化（algotune、gso、mlgym-bench、replicationbench、researchcodebench）、假设检验（arc_agi_2、kumo）、多 agent（cooperbench）、搜索（gaia、financeagent、BrowseComp-Plus）。核心分析是"原语 × 任务族的增益矩阵"，看对角线是否明显。

- **为什么放弃**：P1 已被 ACM、ContextPilot、VISTA、Scroll 做成可恢复；P5 是 Manus 的 todo.md、planning-with-files、MemGPT 核心记忆的组合；P2/P3 的环境回滚是工程难点；作者自己试过 `ctx_archive` 和 `subagents`；ContextEvo 已经在走"迭代 harness、打赢主流 harness"这条路。
- **并入的部分**：P5 的"状态放尾部、对缓存友好"并入了自适应绑定的布局。

### B3. "工作记忆"命题（用户转来的另一份分析）—— 放弃

- **原论点**：论文里的 CLM 本质上是"被预算逼出来的垃圾回收"；让模型从第一步起就把上下文当成自己设计的工作记忆来维护。三个部件：模型自己设计结构、尾部状态区、跨任务保留。关键实验是"不设限预算下仍有提升"。
- **核实结果**（见 [research_log.md](research_log.md) §2）：
  - 说对的：TerminalBench 2.1 只打平；RL 在小模型上只打平；技能演化只在合成任务上；多 agent 没开源；
  - 需要修正的："编码任务只打平"不准确（TBLite 73.7 vs 67.0）；"所有结果都在 32K"不准确（EdgeBench 128K、集群 272K）；"可变状态基本没被开发"说重了（ContextBench 的 Sudoku Sketchpad 和 KV Store 就是可变状态；集群 orchestrator 163 次原地编辑维护计分板，也反驳了"预算放开后模型不编辑"）；Pi 插件已有 `notes` 块雏形；漏了 MemGPT/Letta。
- **为什么放弃**："工作记忆"在 2026 年已经非常挤：Scroll、SKILL.state、PoS、ContextEvo、CLM 作者本人。

### B4. Forget the trace, keep the lesson（去污染）—— 暂缓

- **论点**：Manus 说"把错误留在上下文里"；Why Retrying Fails（2605.08563）拟合出失败尝试留在上下文里时重试错误率是干净上下文的 7.1 倍，并证明"清空后重启"占优。CLM 是唯一能"删掉失败过程、只留一句教训、环境状态不动"的范式，介于两者之间。
- **区分**：Reflexion 是跨回合重启带反思；Sculptor 只能隐藏片段；SKILL.state 直接丢弃全部历史。
- **第一周验证设计**：dict_sum + Prosus Vending Bench（或 Terminal-Bench 2.0 子集）；不设预算上限；四个条件（只追加保留错误 / 失败后清空重启 / 原版 CLM / CLM + 删掉失败轨迹、教训写进尾部状态区）；指标是第一次出错后的单步错误率比和最终成功率。
- **为什么暂缓**：用户把方向转到了"状态派"那一波论文。
- **重启条件**：主线的 H2（错误是否粘住）做完后，"删掉错误只留教训"可以作为降低写入误差持续性的一种干预。
- **2026-10-03 更新**：作为 F2（= [clm_entry_points.md](clm_entry_points.md) 的 E2）重新提出，并扩展成"成对的沉默错误、谁来做手术、自我洗白"。新的撞车：*Feedback That Backfires*（2608.23651）、*Self-Correction Illusion*（2606.05976）、*When Can Agents Forget Their Reasoning?*（2609.29875）。重启要用户确认。

## C 组：状态派的切入点（2026-10-03）

### C1. 早绑定 vs 晚绑定：解释"状态什么时候比历史好" —— 并入（成为主线的理论内核）

- **论点**：显式状态是早绑定（写入时押注以后需要什么），历史是晚绑定（推迟到读取时）。胜负取决于未来信息需求的可预测性。
- **引子的变化**：最初用 SKILL.state 的 InterCode CTF 数字作为"状态 + 历史并存最差"的反常结果，后来发现**是误读**（见 C2）。
- **撞车**：delayed-relevance（10 月 2 日）在单一合成环境上测了延迟相关、事后更正和缓存成本。
- **现状**：发展成主线的"写入时付代价 vs 读取时付代价"。

### C2. "状态和历史并存反而最差" —— 放弃（前提不成立）

- **误读**：SKILL.state 在 InterCode CTF 上 54.2 / 46.4 / 41.8。我把 41.8 读成了"状态 + 完整历史"。
- **实际**：46.4 是带**记忆摘要**的 ReAct；41.8 是 **LangGraph** 实现的 Stateful agent。论文没有测"状态和历史并存"。
- **剩下的真问题**：历史里原记录和更正同时存在，每步都要重新解决矛盾（18/82）。这成了 I3。
- ⚠️ **2026-10-03**：18/82 主要是探针伪影（更正通知与历史矛盾），见 [validation_2026-10-03.md](validation_2026-10-03.md) §2.2。I3 的真问题改为"通知与历史冲突时谁来裁决"。
- **探针上的初步数据**：`state_log`（日志 + 末尾状态）在 explicit 场景 3/3，没看到"并存更差"。

### C3. 各种表示方式的真实服务成本 —— 并入（作为报告维度）

- 现有论文只数 token；CLM 有 prefix-reuse FLOPs 和 SCR。
- 被 delayed-relevance 抢先了缓存分析。只剩 SCR 那条（需要 GPU）。
- 现在作为每个实验都报告的三个成本口径之一。

### C4（= D 方向）. 可验证、事务化的状态 —— 放弃

- **曾经首推**：delayed-relevance 实测"状态写错"是 Sonnet 上的主要瓶颈；SKILL.state "先提交后执行"有文档记录；PoS 只做一致性校验。机制：执行并看到结果后才提交、失败时回滚；每个字段引用日志证据编号；冲突时回到原始证据重新推导。
- **撞车**：MemTX（2607.23929）、MemTxn（2607.27834）、PatchOptic（2607.05483）、PatchBoard（2605.29313）、State-Bound Evidence（2607.24604）、2606.22030（来源上限的投毒防御）。
- **现状**：降级为自适应绑定的部件 ④，不作为卖点。

### C5. 多 agent 共享状态（黑板） —— 放弃

- CooperBench 有 652 个双 agent 任务，CLM 天然支持多文件。
- 撞车：PatchBoard、MemTX、共享记忆的认知准入基准（2609.30813）；SKILL.state 把多 agent 合并列为范围外，复现项目也在讨论合并规则；CooperBench 的 harness 固定。

### C6. 再做一个状态跟踪基准 —— 放弃

StateMemBench、微软 STATE-Bench、WorldLines、BeliefShift、Supersede、DreamBench-SWE 都已经有了。

### C7. 让模型自己写环境模型或 schema —— 放弃

Schema（2609.39140）已在 ARC-AGI-3 上从 58.7% 做到 99.2%。

### C8. 用 RL 训练状态更新 —— 放弃

Supersede、Agent-BRACE、From History to State 已经做了，而且需要大量 GPU。

### C9. 只比较压缩策略的系统研究 —— 放弃

Beyond Token Savings（2609.32961）约 3.5 万次运行已经做了。

| **I3** | 历史在更正后失败，是新旧矛盾还是缺唯一真相来源 | 读取误差里的"干扰"项；拆成 M1 干扰和 M2 重建负担 | `raw` 6/9，错误以重建为主；作废标记、删除、状态在明确更正场景下都是 3/3 |
| **I4** | 在动作发生的那一刻再取回需要的事实 | 自适应绑定的部件 ③ | 约束型漏项只召回候选就能修好（0/3 → 3/3）；机会型漏项必须同时召回被挤掉的选项（0/3 → 3/3） |

中间有一次命名混乱：我曾把 I3 改名为"作废标记 vs 状态"单独推荐，读起来像一个新 idea。实际就是 I3，只是假设细化了。

### I3 单独成文的扩展方案（后被主线吸收）

当时针对"I3 能不能撑起一篇完整论文"的回答：按冒烟测试的形态最多是 workshop 短文，要扩成完整论文需要：
- 三种失败机制的框架（干扰、重建负担、覆盖缺失）和干预识别表；
- 3 个领域的探针、4 个难度旋钮（日志长度、作废条目数、干扰密度、明确/隐式）、规则读者测试；
- 主结果是机制占比相图（横轴日志长度或状态变化次数，纵轴模型规模）；
- 真实基准验证（LongMemEval-KU 四条件、ALFWorld 注入环境变化、LOCA 可选）；
- 闭环实验和"模型自写作废标记"方法；
- 成本 Pareto；
- 机制分析：知道 vs 用上、位置效应、注意力分析（需开源模型和 GPU）、动作时刻修复的不对称。

这套方案的大部分内容都进了主线。

## F 组：CLM 天然占优的切入口（2026-10-03）

用户的问题："有没有 CLM 能做好、传统记忆系统或 harness 做不好的任务？给三个有 insight、有方向、有资源的切入口。"用 21 个子 agent 的只读调研工作流得出，完整设计见 [clm_entry_points.md](clm_entry_points.md)。

**元结论**：对抗审查认为，6 个候选的优势都能被"传统 harness 加一个设计好的工具"追平，但每个候选需要的工具不同。所以入选的三个都配了匹配基线和判死条件，测的是 CLM 剩下的余量。

### F1（= E1）. 迟到的、按属性划范围的更正 —— 候选

- **论点**：按事先没人想到的属性划范围的迟到更正（"第 10–40 步由 EDGE-4 扫描的入库都记错了"），需要原始属性、可执行的批量改写、修掉已写下的派生物三样同时具备。CLM 相对"保留日志 + 代码 + 追加视图"的余量只有"原地修派生物"一项；它最省钱的"读完就压"又会先删掉审计字段。
- **判死**：CLM-EDIT 比 RAW+CODE-APPEND 多对不到 1/6。
- **撞车**：MemoRepair、Rollback Repair、TEPA、Revoked but Still Authoritative 都做了"有来源图的外部记忆"[S]。

### F2（= E2）. 被拒之后的上下文手术 —— 候选

- **论点**：留下世界的反馈，删掉自己连带写错的东西。规则钩子只能修字面命中的根，修不了"成对的沉默错误"；CLM 让执行模型自己当懂推导的编辑者，但可能自我洗白。
- **判死**：阶段 0（真实轨迹重算）显示错误成串比控制难度后 < 2；或 CLM-SELF 比 HOOK 好不到 3/12。
- **来历**：B4 的重启和扩展。撞车很密，新意只能落在不可重置的闭环、成对错误、谁来做手术、自我洗白。

### F3（= E3）. 没有线索、还会被撤销的前瞻约束 —— 候选

- **论点**：没有检索线索时，可恢复的删除等于删除；能走通的只有"到达时绑定"和"去噪"两条路。只追加的钉子在撤销、改范围、累积时会坏，所以绑定的一方必须能清理。CLM 两条路都能走，但自己的压缩成了新的丢失通道。
- **判死**：CLM 自压缩时最旧的通知 ≥ 90% 被删；或撤销探针里 PIN 不比 SCRATCH 差。
- **最大的反面证据**：*Delivery, Not Storage*（2607.20972）的数据显示 agent 主动使用记忆为 0，主张投递必须由 harness 保证 [S]。

### F4（原 C2）. 派生结论的真值维护 —— 放弃（并入 F1）

- **论点**：根事实被更正以后，瓶颈是写下来的派生结论（台账、计划、旧推理）。CLM 能用 grep 传播更正，但默认的覆盖写会毁掉可审计性。
- **放弃原因**：
  - 撞车最重：PlanFence（2609.03340）、StateAuditor（2608.01619）、STALE 的 Type II 加 CUPMem、NeuSymMS/IMPACT-CYCLE 已覆盖这个现象，也占了"Doyle 式 TMS"的说法 [S]；
  - 一行 prompt 的"更正后重写一份最新台账"大概率就能追平；
  - "grep 能传播更正"是人造的：真实派生结论需要重算，字面上不引用根事实。
- **保留**：派生物污染因子并入 F1。

### F5（原 C5）. 把多条前瞻约束编译进决策结构 —— 放弃（并入 F3）

- **论点**：到达时写入有存储、投递、编译三种形态，约束越多、交互越复杂，编译相对笔记的优势越大，但编译错了会静默。
- **放弃原因**：
  - 尾部草稿区加 `str_replace` 就能同样编译；
  - 事件触发的约束编不进静态结构，"约束越多、编译越占优"在机制上自相矛盾；
  - PIS、Constraint Weakening、Governance Decay 已覆盖各个成分 [S]。
- **保留**：约束类型因子、SCRATCH 基线并入 F3。

### F6（原 C6）. 过滤器极性 —— 放弃（并入 F3，只作机制测量）

- **论点**：CLM 用代码批量压缩时，模型写的过滤器本身就是一份它自己定的早绑定 schema；白名单会静默删掉没见过的事件类型，黑名单不会。
- **放弃原因**：
  - 研究的是 CLM 的失败机制，不是优势；
  - 设计者写的黑名单能打平；
  - "未知类型原样保留"一行提示对任何摘要器都有效，TACO（2604.19572）已把它作为设计原则 [S]。

### F7. 成本轴：读完就压 vs 缓存计费 —— 放弃

- **放弃原因**：
  - 需要真实账单或 GPU 上的 FLOPs；
  - 子 agent 的缓存计数分不出编辑位置的差别；
  - delayed-relevance 已做过缓存成本分析 [R]。
- **保留**：三格里留一个示意成本指标。

### F8. 可编辑上下文的安全 —— 维持暂缓（同 A1）

- **原因**：
  - CLM 作者已列为未来工作 [N]；
  - 2606.22030 已做投毒防御；
  - 容易被当成实现 bug。
- **保留**：语义层的来源丢失和自我洗白，作为风险面放进 F1、F2。
